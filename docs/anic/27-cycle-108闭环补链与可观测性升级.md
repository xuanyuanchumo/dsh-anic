## 1. 本轮修掉的两类真缺陷

### 1.1 循环坐标漂移（生产事故级，已根除 + 加机器守卫）

**实证**：`HEAD = 02b958c v0.57.0 cycle-107`，但

| 坐标源 | 实测值 |
|---|---|
| `git log -1 --format=%s` | `cycle-107` |
| `.cycles/workflow-state.json.currentCycle` | `cycle-105`（`currentPhase: plan`） |
| `.cycles/cycles/` 活跃目录 | 只有 `cycle-105` |

**后果**：`run-tests.mjs` 把 cycle-106/107 两轮的测试报告**全写进 cycle-105**——
本轮开工基线实测 `[test-evidence] … cycle-105/test-reports/测试报告.md`。
G0 评估报告 / G2 测试报告 / 账本门禁三方共用这个坐标，于是**证据与轮次错配**，
全程**零报错**。这是"观测面看起来正常"的最危险形态。

**根因**：`init-cycle.mjs` 的 `getNextCycleNum` 只扫 `.cycles/cycles/` 目录
（`assets/skill/scripts/init-cycle.mjs:26-34`）——106/107 从未建目录，它就只能
数到 105；而**没有任何一步**会读 HEAD 去对账。

**修复（三层）**：

1. **判据层**：新增 `src/host/evolution/cycleDrift.ts` —— 纯函数
   `detectCycleDrift` 比对 HEAD / 状态机 / 活跃目录 / 归档四个坐标，
   产出 5 个原因码（`HEAD_AHEAD_OF_LIVE` / `STATE_BEHIND_LIVE` / `STATE_AHEAD_OF_LIVE` /
   `STATE_MISSING` / `ARCHIVE_AHEAD_OF_LIVE`）+ `suggestedCycle`。
2. **观测层**：`orgStatus` 的 `cycles.drift` 接入（`src/host/evolution/orgStatus.ts`），
   面板 `renderOrgCycles.ts` 漂流时 `role="alert"` 逐条原因码、一致时给**显式 ✓ 行**
   （"没有漂移"必须是正面结论而不是沉默）。
3. **事实层**：归档 `cycle-105` → `archive/cycle-105`；`init-cycle --cycle 108`
   建本轮工作区并把 `currentCycle` 推到 `cycle-108`。

**验收证据**：`tests/unit/cycleDrift.test.ts`（10 用例，含事故复现）+ 
`tests/unit/orgCycleDrift.test.ts`（4 用例，真实 DOM）。

### 1.2 技术债提案永不关闭（doc 26 §3 B1）

**实证**：`.cycles/tech-debt/debt-E4-2026-11-05.json` 仍 `resolved:false`，
而其根因（G1 任务清单空）早已修复、**E4 当前评估实测 PASS**。
旧分诊器只认 `skill:*` 维度，`E4`/`Q7` 这类**评估维度债务**一律 `unverifiable`
（`src/host/evolution/techDebtTriage.ts` 旧判据表）→ 已修复的债永远悬着并污染下一轮判断。

**修复**：新增 `src/host/evolution/debtFacts.ts`（读最新**活跃**循环评估报告 + 账本门裁决，
带 `reportPath + sha256:8` 证据），分诊器新增维度判据：

| 当前评估裁决 | 裁决 |
|---|---|
| `PASS` | `stale`（条件不再复现，自动关闭） |
| `FAIL` | `reproduced`（仍复现，保留） |
| `SKIP` / 报告缺行 / 无报告 | `unverifiable`（**没证据不等于通过**） |

**与 doc 26 的口径差异（有意为之）**：doc 26 写"G0-G3 全绿时标 resolved"。
本实现**不要求**四门全绿——维度债务的裁决者是**该维度自己的读数**。
若要求四门全绿，一个无关的 G3 红会把"E4 已修好"这个事实藏起来（正是旧缺陷的镜像）。
四门全绿只作为**佐证**写进证据串（`gatesAllPass`）。

**验收**：`tests/unit/debtFacts.test.ts`（6）+ `tests/unit/techDebtTriage.test.ts`（+4 维度用例）。

## 5. 运行时注册范式（输入 L）与内部技能库

研究结论：官方 seam 26 条中本仓消费 9 条（≈35%）。链路真相 =
`register`（scope 层、层内 first-wins、返回精确 disposer）→ `skills/change`（无 diff）
→ `snapshot{skills,complete}`（incomplete 永不缓存）→ `dsh-tool-skill` 首步注入目录
（只 name + 截 500 的 description）→ 每步 digest 比对替换 → `skill({name})` 载入前
`isModelInvocable` 拒绝 + 返回前 `ctx.skills.get` 重读。

**本仓只走到 register**，且有两个真实风险（进 §6 裁决）：
- `skillRegistration.ts:122` 无条件 `log.info('已注册')`——官方 **project 层同名条目直接赢得**
  runtime 条目，工作区放一个同名 `.dsh/skills/<name>.md` 就能静默压制而日志仍绿；
- frontmatter 的 `disable-model-invocation` / `user-invocable` 被静默丢弃（`:66,71`）。

**内部技能库**：新增/更新两篇参考（见 `assets/skills/`）——
`ci-cd-release/references/actions-authoring.md`（Actions 编写面：matrix/cache/concurrency/
artifacts/OIDC/reusable/permissions/pinning，逐条对照本仓 `ci.yml`/`release.yml` 实测）与
`dsh-native-api/references/runtime-registration.md`（上述官方链路 + 本仓差异 + 四个可落地点）。
