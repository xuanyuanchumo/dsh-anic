## 1. 核心问题的裁决

**用户问题**：是否应该逐步将 ai-native-iteration-cycle 项目技能的 L4 级别自主性
**全面地原生实现**为技能插件——各流程插件化后拥有专属的流程状态流转机与对应的模块引擎？

**裁决：不应「全面」原生化；应维持并深化现行「插件原生引擎 + 技能脚本正典」
双层架构，按增量清单继续推进部分流程原生化。**

### 1.1 理由（按重要性排序）

1. **双真相源守卫是差异化资产，全面原生化会摧毁它**。当前 5 个流程
   （gate-check / macro-phase / archive / hitl / auto-fix）都有 script 正典路径与
   native 引擎双实现，`tests/contract/` 差分契约逐字段对账（flowDifferential /
   hitlDifferential / autoFixDifferential / macroPhaseDifferential / archiveDifferential
   五套）。这是「引擎实现漂移检测」的机器守卫——任何一侧语义漂移立即红。若全面
   原生化并废弃脚本路径，守卫对象消失，漂移只能靠单侧测试自证（自证不独立）。
   外部生态无此机制（superpowers/ECC 均单实现）。
2. **L4 的瓶颈不在流程原生化，在三个缺位层**（外部研究结论）：
   - **任务级编排缺位**（最大差距）：有宏观相位 + 微观循环 + 熔断回退，缺
     「plan→N 任务→逐任务执行+独立评审」中层。superpowers 证明这层才是长时自主
     的主力机制——本轮已以文档协议落地（auto-cycle.md「任务级派遣编排」+
     task-list 模板派遣记录表）。
   - **能力对照测量缺位**：信任度累积（70/85 阈值）基于门禁通过而非能力增量；
     skill-creator 的 with/without 对照评估是正确形态（已排期，见 §4）。
   - **触发可靠性未闭环**：L4 隐含假设技能被正确触发；本轮修复的 P1
     （目录描述 800>500 截断）正是这个假设被现实击穿的实例。
3. **原生化成本/收益已过拐点的部分早就做了**。eval-runner / gate-check 等正典
   脚本走 spawnSync 子进程（60-120s 超时面），其原生等价物（gateEngine /
   hitlAudit / bandDetector 等 7 模块 + 5 流程引擎）已覆盖高频路径；剩余脚本
   （init-workflow / quick-validate 等低频引导类）原生化收益低。
4. **DSH 宿主契约现状**：宿主 0.2.x 对插件开放的服务面（tools/webServer/
   sessions/skills）不足以承载「无子进程的全自主循环」——无后台任务调度服务、
   无跨会话执行编排 API。skill-creator 式 spawn 双跑对照在宿主内可落地
   （anic 工具内 spawnSync），但「常驻自主循环」需要宿主级支持，超前于契约。

## 2. DSH 官方规范审计结论（要点）

- **engines 区间复核**：安装宿主 0.2.1-rc.2 落在 `>=0.2.0-rc.2 <0.4.0-0` 内；
  kb 无 0.3.x 升级指南（证据空白区）——0.3 发布时须重跑 j0 + validate 回归。
  0.2.0-rc.2 的四条破坏性变更（dsh-invariants 移除 / schedule bundle 退役 /
  子路径插件清单 / SignInErrorCode）经核对本项目全部天然不受影响。
- **四服务用法合规**：tools.register（parameters/execute(args,exec)/output）、
  webServer（kind:'exact' + disposer）、skills.register（runtime source）、
  sessions.list()——与 kb 契约逐字段一致；P3 偏差：未用官方 defineTool
  （G-IND 独立性换取，smoke 兜底）。
- **轨迹可见性（用户要求项）已闭环**：anic_* 工具调用自动产生 tool/call +
  tool/result 持久会话事件（官方通道，无需额外 API）；invocationFeed 按
  events.md 规范监听 session/event 检 event.type 配对 tools/result——
  动态白盒面板消费同一数据源。本轮新增修复：技能目录描述截断问题（见 §3 P1-1）。
- **桌面端架构风险登记**：web-server.md:9 明示 Electron 走 file://+IPC「不使用
  本服务器」；当前桌面 runtime 实测 http://127.0.0.1:65518 服务 GUI、/anic/* 路由
  两端可达——但若 DSH 桌面端改纯 file:// 架构，插件路由面整体失效，需重估。

## 4. 增量原生化路线图（裁决后的执行清单）

按「先补 L4 缺位层、再补流程原生化」排序：

1. **任务级派遣编排落地**（已做文档协议，下一步）：flows 域评估第 6 流程
   task-dispatch 的必要性——若 DSH 宿主开放跨会话/后台执行 API 则流程化，
   否则维持文档协议 + FlowTracker 可见性。
2. **触发优化循环**（skill-creator run_loop 模式）：trigger-optimize.mjs +
   语料扩至 ~40 例（含 near-miss 负例）+ train/test 拆分；与现有
   trigger-eval.mjs 互补（后者是回归防线，前者是优化器）。
3. **with/without 对照评估**（skill-creator 对照模式）：evalCompare.ts 双跑
   + 报告落 .cycles/evals/benchmark-{N}.json + org 面板展示——把「检查点
   自动审计化」从审工件升级为审实效。
4. **自举状态机中间态 + 迁移合法性矩阵**（P1-6/P1-7，见 §3）。
5. **V-1 ETag 条件请求**（P1-4，见 §3）。
6. **置信度过滤**（code-review 模式）：agent 卡闭合协议加可选 confidence，
   multiAgentTier2 聚合时 <0.7 标「仅供参考」不进裁决。
7. **假指针防护**（daymade 模式）：quick-validate.mjs 加 F 族检查——
   references 指针验证目标文件含所指内容关键词。

## 5. 不做的事（negative space，防漂移）

- **不做五注册表**：FlowRegistry 模式验证了「同 id 首个胜出 + 静态校验 +
  disposer」的正确性，但把维度/门/投影/评审器/面板段都注册表化的收益
  （可插拔性）在单插件形态下没有消费方——HTTP API 面已是等价的扩展面。
  文档 03/12/14 的相应段落以本文为准改口。
- **不做子 fiber 常驻循环**：宿主 0.2.x 契约无此面；「常驻自主」的正确形态
  是宿主级调度（等官方）+ 插件侧流程状态机（已有）。
- **不吸收 ECC 巨型聚合 / SessionStart 注入 / 多 harness 适配层**：与单技能
  深工程定位冲突（详细论证见生态研究报告「不建议吸收清单」，已并入本文档族）。
- **不删脚本正典路径**：见 §1.1 理由 1。
