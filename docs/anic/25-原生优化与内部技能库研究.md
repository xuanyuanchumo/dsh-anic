# 25 · 原生优化与内部技能库研究（cycle-106）

> **性质**：研究文档（v1.0，2026-11-05）。输入源为四路并行研究（A/B/C/D 报告，见 §11 证据清单）
> 加 Lead 第一手源码取证。本文是**裁决与路线图**，不是实现记录——实现的验收以 §9 清单为准。
>
> **核心结论先行**：
> 1. dsh-anic 的**流程骨架已经是原生 DSH 插件形态**（24 工具 / 62 路由 / 双 tsconfig 隔离 / 事件订阅 /
>    runtime skill 注册），真正的"原生优化"缺口集中在**持久化、可观测性、调度、执行体**四个面——
>    其中最重的是**全部自造**（`.cycles/*.json` + spawnSync + 轮询镜像），而官方 seam 已存在。
> 2. 上游范式 `dsh-superagent-prototype` 给的不是"更聪明的 Agent"，而是**注意力预算系统**
>    （`observe` 默认档 + Mandate + revalidate-before-resume + noWait guard）——这三条**直接强化**
>    dsh-anic 既有的"人类在门禁处保留判断权"原则，且与 L4 全自主的授权语义同构。
> 3. git/github/gitee/npm 的操作知识在**本仓零技能形态**（只有 `docs/agents/CI-CD与发布流程.md` 一篇
>    人读手册，Gitee 全仓零覆盖）⇒ 应整理为**8 叶技能 + 1 元技能**的内部技能库，元技能承载自进化。
> 4. **不做的事**（防漂移）：不全面原生化（双真相源差分契约是差异化资产）；不把 `.cycles` 整体搬进
>    `ctx.storage`；不在 headless 下硬 inject `webServer`/`pluginManager`；不用 `ctx.inject` 动态挂载。

## 3. dsh-superagent 深度研究：可迁移的原生范式

### 3.1 授权 = Mandate + revalidate（对应 ANIC 的自主级升降）

| superagent | dsh-anic |
|---|---|
| Mandate 不可变：记录 Policy version / scope / strength / matched rules / sender identity | 自主级升级已记录 `reason`/信任分，但**无"恢复前 revalidate"** |
| 恢复（resume）前必须 revalidate：explicit 直过；inferred 需 `auto` 且规则仍启用；admission 需强度仍满足 | `anic_autonomy_upgrade` 有前置条件表，但**重启后不 revalidate 旧授权** |
| Policy 变更**不取消在途 Ticket**，而是记录 + 投递 `policy-changed` 输入 | 无此语义（策略/门禁规则变更不通知在途流程） |

**裁决**：L4 全自主的授权语义应补 Mandate 化——`autonomy-history.json` 的每次升降级即一次 Mandate，
重启或策略变更后**先 revalidate 再恢复**；`anic_status` 增加 `wouldAct`（未执行意图）审计位。

### 3.2 accept mode `observe` 默认档

superagent 的 proactive 精确定义为两档：`observe`（默认，评估但只记录 `would accept`，不执行）
vs `auto`（评估通过即接受）。**这是 L4 的直接上游范式**：

**裁决**：dsh-anic 的 L4 全自主应默认 `observe`——自主决策先记录"我会怎么做"并让人审，
再切 `auto`。这不是降低自主性，而是**把"未经人类确认的自主动作"从黑箱变成可审计意图**。

### 3.3 noWait guard（对应收敛门禁的可靠性）

`src/app/sessions.ts:69-86`：拒绝 `sleep`、shell `timeoutMs > 30000`、`job_output` wait > 5000。
**理由**：阻塞等待延迟新候选；结果会自动到达。

**裁决**：收敛门禁/评估驱动的 Session 应加等价 guard——`anic_iterate` 是同步等待，
长任务应转后台 job + 短 wait + 事件唤醒。

### 3.4 拒绝语义结构化 + 批量逐项独立

`UserError{code,values}` → HTTP 400/404/409/500；`orchestrator_route` 批量逐项独立、单项失败不中断。
**裁决**：门禁/脚本工具的拒绝返回结构化 `code`+`values`，批量调用逐项独立。

### 3.5 "拒绝的概念"清单 → ANIC 领域规约

superagent 显式拒绝（`docs/001:45-60`）：Ticket 状态**不跟随** DSH Session；Executor 失败**不锁死工具**；
**不从自由文本推断**"在等人"（用结构化字段）；Cross-Source 身份不映射。

**裁决**：为 ANIC 写**领域规约测试**——禁止"流程状态跟随会话""从报告文本推断等待"等反模式。

### 3.6 部署 = 独立 profile + stateDir + 四段退出码 + hourly check

**裁决**：dsh-anic 插件自身（J0 探针、宿主重启）应有独立 stateDir/锁 + 状态脚本 +
退出码约定 + 自愈调度。当前 `pnpm run j0` 是六步协议探针（绝不启停宿主），缺四段退出码与 hourly 自愈。

## 4. 原生优化方案（P0-P2）

> 编号沿用 C 报告的 N1-N11，按"收益/风险/依赖"排序。**实现优先级**见 §9。

### P0-1（结构性）：遥测原生化

- **现状**：`invocationFeed` 环形缓冲(50) + `/anic/api/invocations/live` 2s 轮询 + scoped logger；
  `host/logger.ts` 是唯一 console sink。
- **目标**：工具面调用同时发原生 telemetry 事件；面板优先消费原生事件流，保留 feed 作降级。
- **收益**：去掉自造缓冲/轮询/诊断计数的维护面；纳入宿主 OTel/留存策略。
- **风险**：宿主 0.3.x 事件词汇变化；telemetry 不保证进模型轨迹（保留 `tool/call` 通道）。
- **依赖**：`ctx.get('sessionTelemetry', false)` 可选探测（不硬 inject）。

### P0-2：HITL 接入原生 `ctx.userQuestions`

- **现状**：`anic_hitl`/`anic_flows_hitl` 是**只读审计工具**；`docs/anic/18:52` 自认
  `userQuestionPanels 原生 HITL 未实现`。
- **目标**：H1-H4 需要人类裁决时经 `ctx.userQuestions` 发原生问答，回答回填审计。
- **收益**：补上 L4"全自主"的人类在环最后一块。
- **风险**：UI 依赖服务在 headless 缺席（可选探测 + 降级到工具面）。
- **依赖**：`user-questions` 包（`capability-seams.md:175-176`）。

### P0-3：投影态原生化（保留 `.cycles` 作技能真相源）

- **现状**：skill-converge / autonomy-history / band-history / reload-history 写 `.cycles/*.json` +
  `atomicWriteFileSync`。
- **目标**：**投影类**状态走原生持久化 seam；`.cycles` 仍作技能契约真相源（双写过渡）。
- **收益**：原子性/并发/清理由宿主保证；多实例可见性改善。
- **风险**：不能整体迁移 `.cycles`（技能契约）。
- **依赖**：`ctx.storage`/`ctx.storageDomain`。

### P0-4：脚本代理执行体原生化

- **现状**：gate 已 native（`gateCheckFlow.ts`），但自举链、`anic_evaluate/iterate/bootstrap`、
  build/test 全走 `spawnSync` 脚本/shell。
- **目标**：自举 gate 步改调 native `gateEngine`；build/test 改走 `ctx.subprocess`/`ctx.shell`；
  eval 维度逐步 native 化。
- **收益**：取消信号/超时/沙箱由宿主统一；自举链与面板同源。
- **风险**：脚本正典是**双真相源守卫**的锚——native 化需保留 script 侧做差分契约，否则守卫对象消失。
- **依赖**：native eval 引擎（未实现）；宿主 subprocess/shell seam。

### P1-5：多 Agent 门禁改用 `ctx.subagents`

- **现状**：`multiAgentTier2.ts`/`multiAgentGate.ts` 直接调 `ctx.llm` 做多角色评审。
- **目标**：评审角色作为 subagent，经 `ctx.subagents` 派遣，保留 Tier-1/Tier-2 降级。
- **收益**：任务级编排落地；subagent 轨迹自动进会话事件。
- **依赖**：`ctx.subagents`（`capability-seams.md:247`）。

### P1-6：自举/修复循环接入 `ctx.schedule`/`ctx.jobs`

- **现状**：自举是同步工具调用；`docs/anic/18:38-41` 指出 0.2.x 无后台调度。
- **目标**：`anic_bootstrap_cycle` 支持注册 schedule/job 循环，由宿主驱动。
- **收益**：L4 全自主循环的真实载体。
- **依赖**：`ctx.schedule`、`ctx.jobs`（超前于当前引擎契约，需宿主 0.3+）。

## 5. 内部技能库设计（自进化）

> 详细设计见 `.cycles/research-inputs/D-skill-library-design.md`（392 行）。本文只记裁决与骨架。

### 5.1 裁决：不造巨型技能，做"主干 + 叶技能 + 元技能"三层

| 层 | 数量 | 职责 |
|---|---|---|
| **主干** `ai-native-iteration-cycle` | 1（既有） | 流程脊柱：六阶段 / 七步 / G0-G3 / L1-L4 |
| **叶技能** | 8 | 操作知识与确定性脚本（git/GitHub/Gitee/npm/CI/CD/Token/DSH API/superagent） |
| **元技能** `skill-library-evolution` | 1（新增） | 自进化：取证→评估→补丁→基准→留痕 |

叶技能与主干**不互相 import**，只通过四类契约咬合：
**词表契约**（`dimensions.mjs` A 族）/ **账本契约**（append-only 哈希链）/
**脚本契约**（`SKILL_SCRIPTS` 白名单）/ **路径契约**（`.cycles/` 唯一根）。

### 5.3 自进化机制（元技能七步）

```
快照基线 → 旧评测基线 → 全文取证 → 抽取共享库→修技能 → 契约断言（新旧双跑）
→ 端到端 A/B → 聚合基准 + 镜像同步
```

| 机制 | 实现 | 守卫 |
|---|---|---|
| **三锚一致** | SKILL.md / 脚本版本串 / CHANGELOG + 注册表 | `skill-lib --check` 错误级 exit 1 |
| **契约双跑** | `lib-contract-tests.mjs` 新版 vs 快照 | 旧版必须复现缺陷（否则场景无效） |
| **聚合基准** | `with_skill` vs `without_skill` 通过率 delta | delta 不得下降（升级门槛） |
| **镜像同步** | `.dsh/skills/*` ↔ `assets/skills/*` 逐字节相等 | 0 差异 |
| **补丁生命周期** | `proposed → human-approved → applied → benchmarked → kept\|reverted` | 自带 `rollbackHash`；revert 改历史即 HASH_MISMATCH |
| **信任分 + 熔断** | 契约通过率 × 基准 delta × 账本完整率 × 漂移守卫清洁度 | 升级需人类、降级可自动（12 号宪章） |

## 6. git/github/gitee/npm 操作知识库要点

> 完整内容由叶技能承载。以下是**裁决与关键事实**（全部本仓实测）。

### 6.1 分支与提交

- 分支：`master`（永久主干）/ `feat/<域>-<主题>` / `fix/<issue>-<主题>` / `chore/<主题>`（合并即删）。
- 主干只进验证过的提交：push 前必须 `typecheck && test && build` 全绿。
- commit：`<type>(<scope>): <一句话结论>`；版本收口提交以 `v0.X.Y cycle-N:` 开头。
- 主干回退用 `git revert`（保历史），**禁止 force-push 主干**。

### 6.2 CI/CD

- 顺序即依赖：**build → typecheck → lint → test**（`ci.yml`）。
- `pnpm install --frozen-lockfile`；`autoInstallPeers=false`（pnpm-workspace.yaml）；Node 22；`ANIC_SELF_AUDIT=0` job 级。
- 不跑 `--live`（真实宿主 E2E 需本机 DSH 桌面端+Chrome，CI 不具备）——**显式跳过并说明，不是假绿**。
- 发布：tag push 触发；tag ↔ `package.json.version` 硬校验；CHANGELOG 版本段存在性校验；
  四件套复跑；`pnpm pack` 重命名稳定名 `dsh-anic.tgz` + sha256；`gh release create`；npm publish 可选。

### 6.3 npm 发布（本机实测坑位）

1. `vault_run` 默认 cwd 是 desktop profile——必须让 npm 进程 cwd 落项目目录。
2. npm 11 不把裸 `NPM_TOKEN` 当凭据——需 `.npmrc-publish` 写 `//registry.npmjs.org/:_authToken=${NPM_TOKEN}`。
3. 新包首次发布后 registry 先呈现 `0.0.0-stage`；`409 Cannot publish over previously staged version`
   表示已在审核/传播队列，**不是失败**。

### 6.4 Token/SSH

- DSH 凭证库：`vault_set/vault_run`，明文永不落盘/入对话；`env` 注入子进程（`GH_TOKEN`/`NPM_TOKEN`）。
- Windows 下 github.com 443 直连可能被重置，而 `gh` API 与 SSH 443 通——**remote 用 SSH 形态**；
  `ssh -T git@github.com` → `Hi <user>!` 即通。
- `.npmrc-publish`（含 token 占位符）在 `.gitignore`，**永不提交**。
- H1 检查点：涉及真实凭据须隔离方案；`ctx.get(name,false)` 探测存在性，避免 strict 杀死 loading 中的 provider。

### 6.5 Gitee（全仓零覆盖，新建技能）

- 本仓 remote 仅 `origin → git@github.com:xuanyuanchumo/dsh-anic.git`；**研究时点**全仓 grep `gitee`
  在业务面零命中（本轮新增 `assets/skills/gitee-mirror-sync/` 后该覆盖已建立——本条描述的是
  研究基线，非现状）。
- 凭证库存在 `gitee` 令牌（`vault_list` 实测：gitee/github/npm 三个）。
- 需新建：GitHub→Gitee 镜像策略、MR/Issue 模板同步、`data/plugins/*.yml` 收录规则、镜像漂移检测、
  Gitee 令牌与 CLI 形态、中文协作面差异。

## 8. 与上游范式的模式对照（差异矩阵）

| 维度 | dsh-superagent | dsh-anic | 差异性质 |
|---|---|---|---|
