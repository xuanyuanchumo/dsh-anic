# 24 · 流程可观测的数学模型与落地方案（cycle-90）

> 本档记录 cycle-90 的**数学模型研究**与其落地裁决。纪律：外部材料只作**方法论与工程形态**输入，
> 不作事实来源；dsh-anic 侧的所有现状陈述都是**本轮实测**得到的（附复算命令）。
>
> **核心结论先行**：本仓的流程数据只支持**三个**模型（KM 生存分析 / EWMA 控制图 / 分位数+Gini）；
> 另外**八项**模型经实测判定**不适用**，逐条写明否决理由（§4）。选型标准是
> **数据够用 + 无偏 + 不依赖归属字段** —— 最后一条最关键（97% 的 flow 是孤儿，
> 任何依赖 cycle/phase/gate 归属的统计都会被幸存者偏差污染）。

## 1. 选中的三个模型

### 1.1 KM 生存分析 —— `src/host/runtime/gateSurvival.ts`

**生存时间口径**：**一个门「失败 → 修复 → 通过」的 episode 时长**。

> ⚠️ **不是**「门禁流程耗时」—— 账本**只记裁决与时间戳，不记开始时间**
> （实测 232 条中「含耗时」的 0 条）。那个口径**不可观测**，不用它是因为
> 「算不出来」比「换个口径」更诚实。

**为什么用 KM 而不是均值/中位数**：修复时长是**右删失**数据（还没修好的 episode 是删失，
不是失败）。均值会把删失样本当成「已修好且很慢」或直接漏掉 ⇒ 系统性偏。KM 是处理删失的标准估计器。

**实测读数**：34 episodes、0 删失 ⇒ 中位 **233641ms（3.89min）**，
CI **[112884, 26393819]ms（1.88min ~ 7.3h）**。

> 上界 7.3 小时是**真实长尾**（有一个 episode 修了 7.3 小时），不是 bug。
> 面板如实显示 —— 把 7.3h 显示成 6.4min 才叫撒谎。

**四条数值稳定性硬要求**（每条都有测试钉死）：

1. **同刻聚合**：同一时刻的多个事件算**一步**（`d` 个事件 + `c` 个删失合并）。
   逐条处理会把同一时刻的多个事件算成多步 ⇒ 生存率阶梯错位。
2. **`n_j === d_j` ⇒ Greenwood 分母为 0** ⇒ CI **退化为 [0,1]** 并标 `degenerateCi`，
   **绝不返回 NaN**。
3. **退化必须逐点判定**：最后一步必然 `atRisk=1, d=1` 触发分母 0。若把它当**全局**退化，
   会把**健康的中位数点**（`atRisk=18, d=1` ⇒ 方差 0.0294 正常）的 CI 误杀成 null。
   ⇒ 用 `degenerateFrom`（首个退化时刻），只有 `degenerateFrom <= medianStep.t` 才算中位数 CI 退化。
4. **`S(t)` 单调不增但可能持平**（某时刻只有删失没有事件）⇒ 反解 CI 时**不能用 `break` 提前退出**
   （持平段会让后面的步骤又满足条件而被漏掉），必须扫完全部步骤取**首个**满足者。

**CI 口径的裁决过程（值得留档）**：本研究曾报 `[145322, 375635]ms`，**该数推不出来** ——
它隐含 Greenwood 半宽 0.1646 ⇒ se=0.08398，但手算的中位数处 Greenwood **方差** = 0.02941
⇒ **标准误 = √0.02941 = 0.17150** ⇒ S 的点态 CI = `0.5 ± 1.96×0.1715 = [0.1639, 0.8361]`，
**不是** `[0.3354, 0.6646]`。⇒ 根因是**把方差当成了标准误**（忘了开方）。

**最终采用的口径**：**CI = { t : 0.5 落在 t 处的 log-log 置信带内 } 的时间跨度**。
不采用「上界曲线首次 ≤ 0.5」—— 中位数附近 `se_log` 大 ⇒ 上界曲线**始终 > 0.5**
⇒ 该口径下 CI 恒为 null（实测）。

### 1.2 EWMA 控制图 —— `src/host/flows/controlCharts.ts`

**对象是 run 级**（`n_i = 1`）：账本是**逐条追加**的，一次 `gate-check --gate all`
会连写 G0/G1/G2/G3 四条。不聚类的话，一次跑里的「3 PASS + 1 FAIL」会变成 4 个独立观测
⇒ **掩盖连续失败**。

**run 聚类是启发式**（gap ≤ 5s 视为同一次跑）⇒ 面板**必须**显示该口径
（`flowLifecycle.runBoundary`）。

**实测读数**：111 runs、p̂ = **0.7658**、**0 越界**。

**为什么不能复用 band-detector 的 WE 规则 4–8**：那些规则作用在**连续值**序列上，
对 0/1 **二项**序列**必然假阳性** —— p̄=0.77 时「连续 8 点同侧」是**正常二项涨落**
（概率约 11%，每 9 个 run 就出现一次）。⇒ **只用规则 1**（1 点超出 3σ）。

**⚠️ 3σ 在本口径下几乎不可达（实测，必须诚实呈现）**：

```
run 级 n_i=1 ⇒ σ_p = √(p̄(1−p̄)) = 0.4235
LCL = p̄ − 3σ_p = 0.7658 − 1.2706 = **−0.5048** ≤ 0  ⇒ 比例不可能低于它
```

⇒ 实测 **30 连败也不报**（100 PASS + 30 FAIL 才触发）。这不是 bug，是**伯努利比例控制图的
固有灵敏度代价**（n_i=1 时抽样方差极大）。

**诚实的表达**：报 **σ 数地板** —— 连续失败 k 次后 `Z_k = p̄(1−λ)^k → 0`，
故距中心线 `→ p̄/σ_p = √(p̄/(1−p̄)) ≈ 1.81σ`（**与 k 无关**）⇒ **3σ 永远到不了**。

面板显示「3σ 规则在本口径下触不到（EWMA 距中心线最多 1.81σ）」，
**而不是**编一个「需要 30 次失败」的数字（那个 N 无穷大，报它是误导）。

**若将来要「连败 3~5 次就报警」**：① 降 L（3→2，假阳性上升）；② 改子组级 n_i=10
（σ 窄 3.9 倍）；③ 用规则 2（同侧越限）—— 但那正是被否掉的规则 4–8 同族。
**本轮选 (a) + L=3，并把灵敏度代价明示**。

### 1.3 耗时分位数 + Gini —— `src/host/runtime/durationStats.ts`

**P95 必须报两个口径**：Type 7 线性插值 vs 最近秩，实测差 **26%**（n=35 时
3162.20 vs 3984ms）。Type 7 适合描述分布形状；**最近秩是 SLA 口径**
（「95% 的请求在 X ms 内完成」指第 95 百分位的**实际观测值**，不是插值值）。
只报一个会误导 —— 报 Type 7 去做 SLA 判断会**低估**。

**Gini 必须报两个尺度**：原尺度 **0.8349**、对数尺度 **0.1995**。
差距这么大说明：原尺度的高 G 主要来自**少数极慢的离群点**，而不是「普遍不均衡」。
对数尺度压扁长尾后 G 骤降 ⇒ 真实情况是「大多数很快 + 少数很慢」。
只报原尺度 ⇒ 误判为「整体不均衡」；只报 log G ⇒ 掩盖「尾部确实很重」。

**形态判据必须看绝对量**（本轮实测踩到）：只按比值判会把
「原尺度 0.045 / log 0.0095」的**均衡**样本误判成「长尾」。
⇒ 两条**同时**成立才算长尾：① 原尺度 G ≥ **0.3**（确实不均衡）② log G < 原 G × **0.6**。
阈值导出为 `GINI_SHAPE_THRESHOLDS`。

## 2. 共用判据件 —— `src/host/runtime/statVerdict.ts`

统计读数有**第三种**状态，不能只靠「有没有数据」区分：

```
有数据且可判定 → ok
有数据但样本不足 → insufficient-data   ← 最容易被伪装成 ok 的那一种
数据形态不适用 → not-applicable        ← 模型选择错误，不是数据问题
```

混进 `ok`（给一个数）是**统计上的撒谎**；混进 `0` 是**数值上的撒谎**（0 是个合法的读数）。
`null` 也不能区分「算出来是 null」与「算不出来」。

**截断检测**：flow-tracker 容量 200、**滚动淘汰最旧的** ⇒ 淘汰后保留窗口**偏向近期**
⇒「近期优于历史」可能是**假象**。实测当前 105/200 **未淘汰**，但每 95 次调用就会触发第一次
⇒ **必须**实现检测（`truncationInfo` + `truncationWarning`）。

## 3. 归属缺失导致的三个真实偏差（必须处理）

1. **时间选择偏差**：有归属的 4 条全来自最近 5 天，孤儿全来自前 13 天 ⇒ **两者不是同一总体**。
2. **幸存者偏差**：`§cycle-N` 只覆盖 47/232 ⇒ 用它做循环级分析会系统性丢弃最老循环。
3. **门禁调用选择偏差**：`G0>G1` 占 34% ⇒ 轨迹熵反映的是**调用习惯**不是流程变短。

⇒ 上述三个模型都**不依赖归属字段**（这是选它们的主因）。
⇒ 但面板**仍须常驻**诚实条：「归属覆盖 3.8%（101 条孤儿不参与按门分组统计）」。
⇒ **禁止**用 workflow-state 现值回填历史。

## 4. 明确**不适用**的八项（逐条含实测理由）

| 模型 | 不适用理由（实测） |
|---|---|
| 马尔可夫**概率**估计 | **guard 使转移依赖外部裁决数据 ⇒ 违反马尔可夫性**；且 gate-check 只有 4 条事件（每单元 n=1）、history 明显不完整。可降级为 Tarjan SCC **纯结构分析**（`macro-phase` 是 DAG ⇒ 永不死循环；`auto-fix` 有 `ITERATING→ITERATING` 自环，实测 3/4 TIMEOUT，median 240s ⇒ **含自环且无出边 ⇒ 结构性死循环；含自环且有出边 ⇒ 条件性循环，静态不可判定**；`hitl` 实测 RUNNING→BLOCKED→RUNNING 打了 **6 圈**） |
| 互信息点估计 | MLE 0.0464 nats，但 **Miller-Madow 校正量占 32% ⇒ 几乎全是噪声**；且 G0/G3 的 FAIL 期望频数 4.1/4.7 < 5 ⇒ **χ² 近似不合法**，必须用 Fisher 精确检验 |
| 门禁「耗时」KM | 账本**无开始时间**（232 条中「含耗时」的 0 条） |
| PageRank / 中心性做瓶颈 | 4 节点 DAG 退化为拓扑序，无信息量 |
| 序列模式挖掘 | 14 条轨迹只挖出平凡项集 |
| 耗时预测 / AUC 作告警 | AUC 全局 0.5755、最小可检出效应 d≈0.96 ≫ 实际效应 ⇒ **只能作负结果** |
| H1–H4 任何统计 | 账本中 **H 门 0 条**（不存在） |
| 轨迹香农熵 | 门禁调用选择偏差（`G0>G1` 占 34%）⇒ 熵反映调用习惯，不是流程长度 |

## 5. 落地与接线（最终形态）

| 文件 | 职责 |
|---|---|
| `src/host/runtime/statVerdict.ts` | `Verdict<T>` 三态 + `truncationInfo` + `truncationWarning` |
| `src/host/runtime/durationStats.ts` | Type7/最近秩双口径 + Gini 双尺度 + 形态判据 |
| `src/host/runtime/gateSurvival.ts` | KM 估计器（Greenwood 方差+标准误双字段 + BC CI + 逐点退化） |
| `src/host/runtime/gateSurvivalTypes.ts` | KM 形状声明 |
| `src/host/runtime/failEpisodes.ts` | 账本 → FAIL→PASS episode 切分（逐门独立） |
| `src/host/flows/controlCharts.ts` | run 聚类 + EWMA 控制图 |
| `src/host/flows/ewmaTypes.ts` | EWMA 形状声明 |
| `src/host/runtime/lifecycleMetrics.ts` | 投影层（窗口/归属/三个模型 + 诚实边界一起返回） |
| `src/host/routes/lifecycleMetricsRoute.ts` | `GET /anic/api/flows/lifecycle` |
| `src/client/features/flows/lifecycleTypes.ts` | 客户端契约（形状 + 守卫 + 派生函数） |
| `src/client/features/flows/renderLifecycleMetrics.ts` | 编排层渲染 |
| `src/client/features/flows/renderLifecycleModels.ts` | 生存分析 / 控制图读数块（解释与实现同处） |

**路由注册形态的坑**：闭环体检的路由族扫描器认的正则是
`/(?:webServer\s*\.\s*)?register\s*\(\s*\{/` —— **`register` 与 `(` 之间不允许有 `!`**。
用 `ws.register!({...})` ⇒ 扫描器看不见 ⇒ 该路由被判「幽灵消费」（客户端引用了未注册端点）
⇒ 闭环体检整族红。⇒ 路由注册**一律**走 `reg(path, handler)` 形态，**与扫描器判据同源**。
