# 工作台重构设计（cycle-110 · W 战线）

> 目标（用户原话）：「将本插件前端界面优化开发成一个现代化的工作台，符合现代化响应式的界面（当前功能不清晰）」。
> 本文是**实施设计**：信息架构、组件边界、契约约束、验收判据。实现细节由代码与测试承载。

---

## 1. 诊断：为什么「功能不清晰」

现状（cycle-109 时点）是 **16 个分区挤成一条纵向长卷**：

| 症状 | 根因 | 证据 |
|---|---|---|
| 打开后不知道能干什么 | 没有信息架构——16 个分区平铺，无分组、无导航 | `panelSectionOrder.ts` 单数组线性堆叠 |
| 找一个功能要滚很久 | 单列 + 全部折叠 + 每个分区只有一条 11px 摘要行 | `renderFoldableSection` 默认 `defaultOpen=false` |
| 屏幕利用率低 | 宽容器下仍是单列（容器查询只用于图区内部） | `panelCss.ts` 无分区级网格 |
| 分区健康状态不可见 | 折叠后只有标题行，红/黄信号藏在分区内部 | 各 render* 自行着色 |

**不是**数据面问题：16 个分区的数据管线（store / 2s·4s 轮询 / 隔离守卫）在 cycle-42..109 已收敛，
本轮**零改动**——只重构「分区如何被组织与呈现」。

## 2. 信息架构：六域工作台

16 分区 + 工作区徽标按**用户意图**（而不是数据来源）分六域：

| 域 id | 标签 | 分区（既有 key） | 布局 |
|---|---|---|---|
| `overview` | 总览 | graph · live · cycles | graph/live **通栏**，cycles 半宽 |
| `health` | 健康与自主 | org · skillHealth · techDebt | 半宽×3（窄容器自动折行） |
| `flows` | 流程与治理 | flows · ledger · hitl · budget | 半宽×4 |
| `diagnostics` | 步骤与诊断 | stepTrace · diagnostics | 半宽×2 |
| `quality` | 闭环与自举 | closure · bootstrap | 半宽×2 |
| `settings` | 配置 | config | 通栏（唯一可写面，保持最后） |

排序判据（与旧旅程序的差异是**有意的**）：卡片网格不是线性叙事，
「先看什么」由导航承接；`health` 提前——自主级仪表带是**英雄指标**，
用户第一眼要看到"现在系统什么状态"；`config` 仍最后（观测面先于可写面，纪律不变）。

- **工作区徽标**在网格**之外**（顶部通栏条）——它是"你在看哪一块"的全局上下文，不属于任何域。
- **节点详情抽屉**（`renderNodeDetail`）在网格之后渲染（overlay，不参与布局）。

## 3. 组件边界（全部新文件，旧文件最小改动）


改动面：
- `WorkflowGraphPanel.ts`：`...renderPanelSections(...)` → `renderWorkbench(...)`（同参透传）；
  工具栏 / prefs 抽屉 / 数据管线**逐字不动**。
- `panelCss.ts`：`PANEL_CSS` 数组末尾追加 `WORKBENCH_CSS`（单一注入点不变）。

## 4. 数据结构与算法

- **域表**：`WORKBENCH_DOMAINS: readonly { id; labelKey; span: 'full'|'auto'; sections: readonly SectionKey[] }`
  ——分桶只有一个真相源；`partitionSections` 是**纯 zip**（装配序 × 域表），
  任何分区漏配/重复配在单测红（反向自检：从表里删一项必红）。
- **域状态分类**：`classifyDomainStatus(state)` 读既有 store 切片，
  规则（严重度优先 `fail > warn > idle > ok`）：
  - `diagnostics`：`check` 有 failure ⇒ fail；未加载 ⇒ idle；
  - `health`：org drift 或 skillHealth degraded/slow ⇒ warn；techDebt 有 critical ⇒ fail；
  - `flows`：hitl 有 pending ⇒ warn；ledger verify 不一致 ⇒ fail；
  - `overview`：invocationsError ⇒ warn；
  - `quality`：closure `ok=false` ⇒ warn；bootstrap 陈旧 ⇒ warn；
  - `settings`：恒 `idle`（可写面不评级——避免把"没配置"画成故障）。
- **响应式**：容器查询三档（继承 `panelCss` 头注纪律——断点挂面板自身宽度）：
  `<560px` 单列 / `560–900px` 两列 / `>900px` 三列；`span:'full'` 的卡 `grid-column: 1 / -1`。

## 5. 契约与纪律（硬约束）

1. **锚点保全**：16 分区的全部 `data-anic-*` 锚点、fold id、locale `fold.*` 键**一个不丢**
   （`panelAssemblyContract` 三腿对账 + smoke 计数守卫原样跑）。
2. **smoke 工具栏 = 3 按钮**：导航条**不得**用 `role="toolbar"` / 不得进 `data-anic-toolbar` 子树
   （否则计数守卫红）；导航用 `nav[aria-label]` + 链接。
3. **新锚点**：`data-anic-wb-root / -nav / -nav-chip=<domainId> / -grid / -card=<domainId>
   / -card-status=<state> / -card-count=<n>`（全可断言；零占位——分区被门控隐藏时卡片不渲染）。
4. **颜色**：只经 `v()`（`var(--anic-*, fallback)`）——裸 `var` 禁令（clientRenderContract）照跑。
5. **T3**：单文件 ≤250 行；`WorkflowGraphPanel.ts` 现 243 行——工作台装配必须**搬出**，
   根组件改动后行数不得上涨超限。
6. **死导出棘轮 P1 ≤ 8**：新模块的导出必须全部被消费（`audit-wiring` 跑绿）。
7. **i18n**：新键进 `locale/zh.json` + `en.json`（parity 契约）；`i18nDeadKeyContract` ⑤ 上界
   610 → N，**逐键写明消费点**（既有纪律）。
8. **中文注释**：文件头回答"本文件存在的原因"，取舍写注释不复述代码。
