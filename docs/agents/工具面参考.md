# dsh-anic 工具面参考（anic_* 22 工具）

> 本册覆盖插件经 `ctx.tools.register` 暴露给 DSH 会话/子代理的**全部 22 个工具**。
> 读取时机：想知道「模型能调用什么」「某个工具写不写盘」「参数默认值是什么」「它和 HTTP 面什么关系」时。
>
> **工具面是 DSH 大模型调用本插件的最低保证路径**（doc13 §1「执行面」）：HTTP 路由面给面板与外部脚本用，
> 工具面给任何会话/子代理用——两者共享同一实现层，但**取证面不同**（见 §4）。
>
> 事实来源：`src/host/tools*.ts`（9 个工具模块，逐个读出）。工具 id 由 `tests/contract/toolIdsContract.test.ts`
> 双向钉死（源码注册 ⇄ README/文档计数）。

无此前缀者是**直调**（`anic_gate_check` 直跑脚本，`anic_flows_gate_check` 走流程机）。两者语义不同，勿混用。

## 2. 逐工具参考

> 参数表只列**模型可见**字段（宿主专用字段如 `timeoutMs`/`isConcurrencySafe` 不模型可见，见 §3）。
> 「写盘」列 = 是否产生工作区副作用（`.cycles/` 写入）——**只读工具不写**。

### 2.1 评估与迭代（`tools.ts`）

| 工具 | 用途 | 参数 | 写盘 |
|---|---|---|---|
| `anic_evaluate` | 质量评估报告（E1-E8/Q1-Q8 维度） | `workspace?`（目标目录，缺省当前工作区）· `dimensions?`（逗号分隔维度 id，如 `E1,E2,E3`） | 是（评估报告 + 可能的健康债务） |
| `anic_iterate` | 一轮完整迭代（评估 + 门禁） | `workspace?` · `timeout?`（单脚本超时 ms，默认 90000；大工作区需加大） | 是（评估 + 账本） |
| `anic_gate_check` | 收敛门裁决（G0-G3） | `workspace?` · `gate?`（默认 all） | 是（`--record` 形态写账本） |
| `anic_bootstrap` | **插件自身**健康自评（自举） | `maxRounds?`（默认 3） | 是（tech-debt 提案） |

### 2.2 自举循环（`toolsBootstrapGateway.ts`）

| 工具 | 用途 | 参数 | 写盘 |
|---|---|---|---|
| `anic_bootstrap_cycle` | 自动驱动完整自举循环（**不**自我改码，R-31） | `workspace?` · `maxRounds?`（默认 3，上限 10）· `timeout?`（每步超时 ms，默认 60000） | 是（`self-bootstrap.json` + 提案） |
| `anic_bootstrap_analyze` | 自举结果深度分析（开发者评审用） | `workspace?` · `maxRounds?` · `timeout?` | 是（分析产物） |

### 2.3 流程状态机（三网关）

| 工具 | 用途 | 参数 | 写盘 |
|---|---|---|---|
| `anic_flows_gate_check` | **经流程机**跑门禁（可得流程状态/流转事件） | `workspace?` · `gate?`（G0/G1/G2/G3/all，默认 all）· `mode?`（`script`(默认)/`native`/`diff`）· `quality?`（默认 true，含质量维度）· `record?`（默认 false；script 传 `--record`，native 追加去重） | 是（`record=true` 或 native 追加） |
| `anic_flows_advance` | 宏观相位推进（plan→design→build→test→deploy→maintain，**前向only**） | `workspace?` · `target?`（显式目标相位；缺省下一相位）· `mode?`（`script`(默认)/`native`）· `dryRun?`（仅 native，默认 false） | 是（相位状态；`dryRun` 时否） |
| `anic_flows_archive` | 循环归档/清理/清单 | `workspace?` · `cycle?`（循环号，要求全部任务完成）· `clean?`（默认 false，**破坏已归档目录**）· `keep?`（保留数，默认 5，仅 clean 时）· `list?`（只读清单；无 cycle/clean 时默认）· `mode?`（`native`(默认)/`script`） | 是（`clean` 时移动/清理归档目录） |
| `anic_flows_auto_fix` | 测试/验证持续失败时的自动修复循环 | `workspace?` · `maxRetries?`（每次运行最大修复尝试，默认 3，上限 10）· `testCmd?`（测试命令覆盖；缺省取 `.cycles/config.yml` 的 `test_cmd`）· `mode?`（`native`(默认)/`script`） | 是（修复尝试记录 + 失败时 incident） |
| `anic_flows_hitl` | HITL 审计闸门的三段修复流（审计→自动修复熔断门→重审） | `workspace?` · `gate?`（H1/H2/H3/H4/all，默认 all）· `mode?`（`native`(默认)/`script`） | 是（审计日志 + 账本） |

### 2.4 技能网关与生命周期（`toolsSkillGateway.ts`）

| 工具 | 用途 | 参数 | 写盘 |
|---|---|---|---|
| `anic_skill` | **跨项目技能脚本调用网关**（15 个白名单脚本） | `script`（脚本名，白名单内）· `workspace?`（目标项目目录——**跨项目调用的正确通道**）· `args?`（字符串数组，附加 CLI 参数） | 取决于脚本 |
| `anic_install` | 安装/引导 ANIC 工作区（bootstrap 新目录） | `workspace?` | 是（建 `.cycles/` + 内联技能） |
| `anic_skill_repair` | 修复技能副本漂移（差异重装） | `workspace?` | 是（重装差异文件） |

> **`anic_skill` 的位置参数铁律（P1 实证，CLAUDE.md 明列）**：项目目录是脚本的**第一个位置参数**
> （`node <script> <workspace> ...args`）。**绝不能**在 `args` 里再传项目目录或 `--project-dir` 旗标——
> 15 个脚本只认 `args._[0]`，误传会产生「双目录」错误（cycle-38 前 6 连失败根因）。
> 网关对误传有 `workspaceRedirected` 回显兜底，但**正解是不传**。替代性 e2e（`skillReplaceE2E`）钉死此约定。

### 2.7 渐进式披露加载器（`toolsIndexLoaderGateway.ts`）

索引模式（`toolDisclosure: indexed`）下这两个工具是**唯一常驻**的 anic 工具——模型取回 schema 的唯一通道。
缺它们则 `indexActivation.activationReady()` 拒绝切档（否则模型自锁：看得见索引却调不到任何工具）。

| 工具 | 用途 | 参数 | 有副作用？ |
|---|---|---|---|
| `anic_tools_search` | 按关键词检索可用能力 id + 摘要（不含 parameters） | `keyword?`（空 = 列出全部） | **否**（只读） |
| `anic_tool_detail` | 取某工具的**完整定义**（回注册面而非索引） | `name`（必填） | **否**（只读） |

**两条纪律**：
1. `parameters` **绝不能**从索引反序列化（索引刻意不含它，含则净收益归零）；一律回注册面取真定义。
2. 这两个工具的 `description` **不得含「anic」「工具」「tool」等泛词**——实测（真实 trigger-eval 扫描）
   它们会抢走既有查询的 top-1（曾使 recall 掉到 24/26）；当前措辞经扫描验证 **26/26 / FPR 0/14**。

## 3. 工具定义形状（官方契约 vs 本仓）

本仓走 **raw JSON-Schema ToolDefinition**（非官方 `defineTool` DSL），官方 `ctx.tools.register` 直接接受该形态
（MCP 路线）。字段铁律逐项核对（`src/host/toolsSlot.ts`）：

| 字段 | 要求 | 本仓 | 说明 |
|---|---|---|---|
| `parameters` | JSON Schema | ✓ | 模型可见参数表 |
| `execute(args, exec)` | **双参** | ✓ | 第二参是执行上下文（取消信号等） |
| `output: {schema, render}` | 必填 | ✓ | `schema` 必须 **object-rooted**（宿主校验） |
| `render` 返回 | `ContentBlock[]` | ✓ | 模型可见的内容块 |
| `presentCall` / `presentResult` | **纯函数**（可回放） | ✓ | UI 卡片渲染；不得有副作用 |
| `timeoutMs` | 宿主专用 | ✓ | **不模型可见**（模型看不到超时配置） |
| `isConcurrencySafe` | 宿主专用 | ✓ | 声明并发安全（写侧工具不标） |

**为什么不用 `defineTool`**：免增运行时依赖（G-IND 独立性守卫 + 零运行时依赖纪律）；DSL 的收益（编译期校验）
在 raw 路线下由**契约测试**替代（`toolIdsContract` / `toolOutputContract` / `presentCallContract`）。

## 4. 工具面 vs HTTP 面：同一实现、不同取证面（**关键差异**）

| 维度 | 工具面（`anic_*`） | HTTP 面（`/anic/*`，61 路由） |
|---|---|---|
| 消费方 | 任意 DSH 会话 / 子代理 | 面板客户端 / 外部脚本 / curl |
| 进 DSH 会话轨迹 | **是**——`ctx.tools.register` 注册的工具经 agent loop 统一分派，自动产生 `tool/call` + `tool/result` 持久化会话事件 | **否**——官方事件词汇表无 HTTP 事件，`dsh-host-webserver` 不 append session 事件（**官方语义，非本插件缺陷**） |
| 进 flow-tracker | **取决于实现路径**：`anic_skill`（全量 15 脚本）与自举编排进；`anic_flows_*` 直调脚本引擎、`anic_bootstrap*` 部分路径**不进** | 同左——HTTP 路由调 `invokeSkillScript` 时同样不进 flow-tracker（除非经 `anic_skill` 网关） |
| 可见性后果 | 轨迹 UI 可见 + 实时调用流可见 | **面板可观测，但模型轨迹不可见**（调试 curl 触发写侧动作时须知此边界） |

> **诚实边界**：面板上的「实时调用」分区消费的是 `session/event` 的 `tool/call`——因此它只显示**工具面**
> 调用与经 agent loop 的动作。HTTP 路由调用、脚本直跑、CI 触发**都不进该流**。这不是面板缺陷，是取证面
> 的客观边界（详见 [可观测性与轨迹可见性.md](可观测性与轨迹可见性.md) §2.2 与 §D 遗漏 2 的 PTC 待收口项）。

## 6. 新增工具的清单（加工具时要动的地方）

1. 落 `src/host/<域>Gateway.ts`（一域一文件；T3 ≤250 行）；共享形状用 `toolsSlot.ts`。
2. 在 `src/host/tools.ts` 的 `anicTools` 聚合数组里登记（宿主入口 `src/index.ts:40` 读它）。
3. 本文档 §2 增一行（`toolIdsContract` 会红直到补上）。
4. 若工具写盘 → `isConcurrencySafe` 不标；若只读 → 标 `true`。
5. i18n：工具 `description` 是**模型面英文**（触发路由用），**不进** `locale/`（`locale/` 只管用户界面文本）。
6. 跑 `pnpm run test`（`trigger-eval` 会计入新工具的触发面）。
