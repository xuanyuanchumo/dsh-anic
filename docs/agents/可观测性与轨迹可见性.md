# 可观测性与轨迹可见性

> dsh-anic 的「动态白盒」承诺：DSH 大模型对本插件的每一次调用，都要**实时、可见、可审计**。
> 本文档定义三条通道、事件接线、诊断计数与验证结论。

## 1. 三条通道（全部实测验证）

| 通道 | 载体 | 内容 | 验证状态 |
|---|---|---|---|
| A. DSH 原生轨迹 | 宿主「轨迹」标签（`dsh-client-ui-trajectory`） | `tool/call` + `tool/result` 标准会话事件，`anic_*` 工具调用天然进轨迹 | ✅ 真实宿主实测（anic_status 出现在轨迹 #38 行） |
| B. ANIC 实时调用区 | 本插件客户端面板「实时调用（动态白盒）」 | 每次调用的 name/参数预览/turn/step/耗时/状态（执行中→完成/失败） | ✅ 真实宿主实测（`anic_status · 完成 · 31ms · t13/s1`） |
| C. Feed API | `GET /anic/api/invocations/live` | 环回缓冲快照 + 诊断计数 | ✅ 真实宿主实测（`total:1, diagnostics:{sessionEvents:14, anicCalls:1, anicResults:1}`） |

**设计立场**：官方没有也不需要专门的「插件调用留痕」机制——任何模型可见的工具调用天然产生标准 `tool/call`/`tool/result` 会话事件（KB 立场：「模型可见即已记录」）。本插件的增量价值在通道 B/C：把**自身**的调用流实时镜像出来，配诊断计数区分「事件没到」与「到了被过滤」。

## 2. 事件接线（`src/host/runtime/invocationFeed.ts`）

双事件通道配对：

- **开始相位**：Cordis 事件 `session/event` 携带 `tool/call`，**载荷在 `event.data` 内**（`{turn, step, callId, name, arguments(原始串)}`）。历史缺陷 P0-FEED-ENVELOPE：曾直接读 `event.callId` 恒 undefined——事件到达但全被过滤，靠 `FeedDiagnostics` 计数发现。
- **结束相位**：Cordis 事件 `tools/result`（`(exec, result)`，`exec.callId` 配对，`result.isError` 判失败）。`tools/result` 经 `scopeTarget(this, exec.agent)` carrier 派发（`dsh-tools/lib/index.js:3409-3427`），observer 异常逐个容忍。
- 过滤条件 `isAnicInvocation`：`name.startsWith('anic_')` 或 `name === 'skill' && rawArguments.includes('ai-native-iteration-cycle')`（技能代理调用也纳入白盒）。
- 监听随插件卸载自动移除（官方 events.md：事件监听器也是效果）。

### 2.1 关键实测裁决（勿反复怀疑）

- **`sessionEvents: 0` ≠ scope 过滤问题**：普通 `ctx.on('session/event')`（不带 `{global:true}`）在真实宿主工作正常——重启后无事件时计数为 0，真实调用后 sessionEvents=14 全部到达。全官方生态 40+ 包均用普通 `ctx.on`。**不要加 `{global:true}`**。
- 参数预览截断 200 字符；孤儿判定 `ORPHAN_AFTER_MS = 15min` 只写在快照副本上（无副作用——曾因写在内部记录上污染后续快照，单测抓出）。

### 2.2 进程边界（cycle-42 · T-4208 文档化）

feed 的两相事件都发生在**宿主进程内**（Cordis 事件总线），面板消费发生在**渲染进程**（Web Client），中间只隔一条 HTTP 轮询：

```
宿主进程                          渲染进程
├─ session/event (tool/call)  ┐
│   event.data 内层载荷        ├→ recordInvocation ─→ 环形缓冲(50, drop-oldest) ─→ /anic/api/invocations/live ─→ useInvocations(2s) ─→ store.invocations 切片
├─ tools/result (exec,result) ┘    isAnicInvocation 过滤         快照即快照（无长连接）      ETag/可见性/退避            LiveInvocationsSection
```

- **无推送**：面板不知道「有新事件」，只按 2s 拍拉快照——「最近完成+运行中」的延迟上界 = 轮询间隔 + 一次请求 RTT（运行中条目的 `startedAt` 在开始相位即写入，所以调用一落地最快 2s 可见，结束相位同拍补齐）。
- **缓冲有界**：宿主侧环形缓冲 50 条 drop-oldest——面板 2s 拍之间发生 >50 条 anic 调用时，中间条目会丢（每拍 total 计数仍如实）；这是**白盒边界**而非隐藏丢失，面板概览行与 FeedDiagnostics 都能看到总量。
- **状态归因**：`in-flight` 判定纯客户端推导——缓冲里有开始相位无结束相位即视为在飞；宿主重启后缓冲清空，面板自然回空（不伪造「全部完成」）。
- **过滤在宿主侧**：`isAnicInvocation`（`anic_*` 12 工具 + skill 参数含 `ai-native-iteration-cycle` 精确 JSON 匹配）在 recordInvocation 前执行——非 anic 调用不进缓冲也不进计数分子，`sessionEvents` 分母仍全量（诊断比值因此可判「被过滤」vs「没事件」）。


## 3. 诊断计数（`FeedDiagnostics`）

`{sessionEvents, sessionToolCalls, toolsResults, anicCalls, anicResults}` 五项计数随每次快照返回，用于白盒自证：

- `sessionEvents>0 && anicCalls===0` → 事件到了但被过滤（接线/命名问题）；
- `sessionEvents===0` → 宿主侧无事件（刚重启/无调用）；
- `anicCalls>0 && anicResults===0` → 调用在飞或结束相位失配。

`feed` 未接线时路由显式 500（`invocationRoute.ts`）：空流 200 会让「未接线」看起来和「没有调用」一样。

## 4. 流程级跟踪（`src/host/runtime/flowTracker.ts`）

`anic_skill` 每次执行前 `startFlow`、后 `finishFlow`，持久化到 `{workspace}/.cycles/flow-tracker.json`（`INVOKING`→`RUNNING`→`DONE|FAILED|TIMEOUT`）。`anic_status` 的 `flowStats` 按脚本聚合 total/success/timeoutMs。已知债务：`'INVOKING'` 状态声明后从未赋值（`startFlow` 直接写 RUNNING）——P3 清理项。

## 4a. 快照数据面的条件请求与轮询纪律（cycle-38 · V-1 收口）

**服务端**（`snapshotRoute.ts`）：

- `GET /anic/api/workflow-snapshot` 现在带标准 **ETag**（`"sha256前16位"`，与 `X-ANIC-Snapshot-Digest` 同指纹）。
- **语义指纹排除 `generatedAt`**——响应体每次都带新时间戳，若指纹覆盖它则 ETag 永不相等、304 形同虚设。指纹只覆盖 nodes/edges/autonomy/counts。
- 请求带 `If-None-Match` 且命中 → **304 空体** + ETag/Workspace 头（省的是响应体与客户端二次渲染，不是快照构建——构建总是要跑的，这是诚实边界）。
- 数据真变（如账本追加）→ 指纹变 → 旧 ETag 不命中 → 200 全量（缓存失效诚实）。

**客户端**（`usePanelFetch.ts`，TanStack Query 轮询纪律吸收，context7 /tanstack/query）：

- **ETag 学习**：每个 target 记住上次响应的 ETag，下轮带 `If-None-Match`；**304 = 数据语义未变**——不重放 `apply`（等价结构性共享：引用不变 → setState 不触发重渲染）、不算失败、触发 `onRecover`。「轮询继续」与「数据未变」是两件事，304 正是轮询的健康形态。
- **隐藏暂停**（`refetchIntervalInBackground=false` 缺省语义）：`document.visibilityState !== 'visible'` 时跳过本轮拉取（定时器照排，可见时自然恢复）。用户不看面板时省掉全部轮询流量——4s 档 8 端点的常态成本显著下降。jsdom/无 fetch 沙盒无此 API → 特性静默缺省（既有行为不变）。
- 无 ETag 的老端点零行为变化（不带条件头）。

**测试钉**：`tests/unit/snapshotRoute.test.ts` V-1 describe 6 用例（304/指纹稳定/数据变失效/无头兼容）；`tests/unit/usePanelFetch.test.ts` cycle-38 describe 5 用例（学习回带/304 不重放/ETag 变化全量/无 ETag 兼容/隐藏暂停）。

## 5. 持续学习与健康度（`src/host/runtime/continuousLearning.ts`）

`anic_status` 返回 `health + healthSummary`：健康等级检查顺序 **slow（超时率）先于 degraded（成功率）**——timeout 是 DONE 的子集，先检查更具体的。`analyzeSkillHealth` 纯函数零副作用。

## 6. 客户端渲染（`src/client/features/live/renderInvocations.ts`）

- `useInvocations(pollMs=2000)` 轮询——**为什么不用 SSE**：宿主 webServer 槽位 exact 路由没有流式契约，多代兼容下轮询是唯一全版本可用通道；失败保留上次数据。
- 三态分支：null（等待首轮，不伪造空态）/ 空流（引导文案）/ 列表；每条含状态点（in-flight 脉冲动画，`prefers-reduced-motion` 逃逸）、`t{turn}/s{step}`、error 或参数预览。

## 7. 验证记录（2026-10-16，真实宿主 3080 + 桌面端）

- 旅程：输入「请调用 anic_status 工具…」→ 模型自主调用 → 三通道同步出现该调用；
- 轨迹历史同时实证了 D4 契约的必要性：旧 bundle（修复前）的 anic_* 调用全部报 `Error: content.some is not a function`，dist 重建+宿主重启后同款调用成功——`output.render` 必须返回 ContentBlock[] 是硬约束；
- 桌面端：ANIC 标签可见（用户确认）、`/anic/api/invocations/live` 200。

## 8. 循环坐标读数（cycle-108）

`GET /anic/org-status` 的 `cycles.drift` 是**第四类白盒通道**：它报告的不是"系统跑成什么样"，
而是"**我们把这个结论记到哪一轮**"。四源比对：HEAD subject / `workflow-state.currentCycle` /
活跃循环最大编号 / 归档最大编号，产出 5 个原因码（`HEAD_AHEAD_OF_LIVE`、`STATE_BEHIND_LIVE`、
`STATE_AHEAD_OF_LIVE`、`STATE_MISSING`、`ARCHIVE_AHEAD_OF_LIVE`）+ `suggestedCycle`。

面板呈现纪律：

- 漂移 → `role="alert"` + 逐条原因码（带坐标数字）+ 建议下一循环；
- 一致 → **显式 ✓ 行**（"没有漂移"是正面结论，沉默会让用户无法区分"没检查"与"检查过没问题"）；
- 旧宿主不返回 `drift` → 整段不渲染（不得伪造一致）。

性能：HEAD 读取有 5s 记忆化（面板轮询端点，git 子进程 ~20-50ms 不可每拍付一次）。
