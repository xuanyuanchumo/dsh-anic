# 自举与健康取证

> 本册回答：**「自举跑到哪了」「技能健康为什么是 0%」「这些数字从哪来」**。
> 读取时机：排查自举不收敛、技能健康面标红、flow-tracker 缺记录、债务队列与健康面不一致时。
>
> 事实来源：`src/host/selfBootstrap.ts`（状态机）+ `src/host/runtime/{scriptParsers,continuousLearning,bootstrapOrchestrator,bootstrapSteps}.ts` +
> `src/host/routes/selfBootstrapRoute.ts` + `.cycles/` 真实工件。每条结论附 `文件:行号` 或工件路径。

## 1. 三份工件的分工（不要混用）

| 工件 | 内容 | 写者 | 语义 |
|---|---|---|---|
| `.cycles/self-bootstrap.json` | 自举**状态机**：`status` / `round` / `maxRounds` / `lastEvalScore` / `lastGateVerdict` / `history[]` | `selfBootstrapRoute.ts`（`/anic/self/*`）· `bootstrapOrchestrator.ts`（`anic_bootstrap_*`） | **当前进展**（唯一状态源） |
| `.cycles/tech-debt/self-bootstrap-round-N.json` | **提案**：`round` / `evalScore` / `gateVerdict` / `gateStderr` / `action` | 同上 | **待评审的改进提案**——`action` 恒为 `REVIEW_REQUIRED — no auto code modification (R-31)` |
| `.cycles/tech-debt/health-<date>.json` | **健康建议**：`id` / `dimension`（`skill:<脚本>`）/ `severity` / `description` / `proposedAction` / `resolved` | `healthDebtBridge.ts`（`skillHealthRoute` 读面旁路） | **技能健康的落盘通道** |

**三者关系**：状态机是真相；提案是它的失败记录；health 是**另一条**通道（技能调用健康 → 债务队列）。
同一份 `tech-debt/` 目录里**混有两种来源**的提案——按 `source` 与 `id` 前缀区分（`self-bootstrap` vs `health-fix-*`）。

## 2. 自举状态机（`src/host/selfBootstrap.ts`）

```
IDLE → EVALUATING → GATE_CHECKING → FIXING → VERIFYING → CONVERGED / EXHAUSTED
```

- `advanceBootstrap(state, evalScore, gateVerdict, fixApplied)` 是**唯一推进器**。
- **只认 `'PASS'` / `'approve'` 为通过**——其余（含 `'unknown'`）**永不推进**（fail-closed）。
- `maxRounds` 到顶 → `EXHAUSTED`（不是 CONVERGED；两者必须可区分）。
- **R-31**：`FIXING` 相位**只写提案不写代码**——自举绝不自动改源码。改动前必须保留此性质。

### 2.1 两个入口，语义有重复（已知结构债）

| 入口 | 实现 | 特征 |
|---|---|---|
| `/anic/self/evaluate` · `/gate-check` · `/iterate` | `routes/selfBootstrapRoute.ts` 内联状态序列 | **不记账**（flow-tracker 无记录——见 §4） |
| `anic_bootstrap_cycle` · `anic_bootstrap_analyze` | `runtime/bootstrapOrchestrator.ts` | 走 `bootstrapSteps.ts`，**有 FlowTracker**，且有 re-gate 复检环 |

> **登记（skill-eco 研究结论 P0）**：两条路径在同 workspace 上可能产出不同 round 语义，
> 属「双实现」结构债。修复方向 = `/anic/self/iterate` 复用编排器（保留 R-31 写侧隔离）。
> 本册如实记录，不代为辩解。

## 3. 解析器：为什么 evalScore 是 0 或 1（不是连续分数）

唯一实现在 `src/host/runtime/scriptParsers.ts`。

| 函数 | 取值 | 判据（脚本真实输出行） |
|---|---|---|
| `parseEvalScore` | `1` \| `0` | `1` = stdout 命中 `/All \d+ evaluated dimension\(s\) passed\./`（`eval-runner.mjs:515`）<br>`0` = stderr 命中 `/dimension\(s\) failed:/`（`:509`）**或输出不可识别** |
| `parseGateVerdict` | `'PASS'` \| `'FAIL'` \| `'unknown'` | `PASS` = stdout `/All gates PASSED\./`（`gate-check.mjs:228`）<br>`FAIL` = stderr `/Gate check FAILED\./`（`:225`）<br>兜底 = 逐门禁行 `/^[ \t]*\[(PASS\|FAIL)\] G\d/gm`（`:198/:219`，LEDGER 行不匹配）<br>`unknown` = 零匹配 |
| `parseFixApplied` | `string` \| `null` | `null` = 无需修复/未验证通过/不可识别 |

**为什么不是 `0.875` 这种数（历史错误的根源）**：三个真实脚本**从不输出** `Overall score: …`
这类行——成功路径只打印**通过维度数**，失败清单在 stderr。连续分数**不可推导**，
故 `evalScore` 忠实二值；`advanceBootstrap` 也不按它分支（只作记录）。
宁可少报精度，不可虚构一个从未存在过的数。

> **义务提醒**：`docs/agents/API参考-自举与技能.md` 曾把这两个函数写成「正则形状契约」
> （`/score:/` / `/GATE:(PASS|FAIL)/`）——那是**虚构格式**，cycle-71 已按真实契约重写该册。

## 4. 取证面：谁进 flow-tracker，谁不进（**关键**）

`flow-tracker.json` 的唯一写入点是 **`anic_skill` 网关**（`toolsSkillGateway.ts`）与**自举编排**
（`bootstrapSteps.ts`）。**不在流里的执行路径**：

| 路径 | 进 flow-tracker | 后果 |
|---|---|---|
| `anic_skill`（覆盖 15 白名单脚本） | ✅ | 唯一「全量可见」通道 |
| `anic_bootstrap_cycle` / `_analyze` | ✅（eval/gate/fix；返回体只回显 eval 流 ID——P1 待补） | 部分可见 |
| `anic_flows_*`（gate_check/advance/archive/auto_fix/hitl） | ❌ 直调脚本引擎 | **不可见** |
| `POST /anic/skill/invoke`、`/anic/evaluate`、`/anic/iterate` | ❌ 直调 | **不可见** |
| `POST /anic/self/evaluate` · `/gate-check` · `/iterate` | ❌（grep `startFlow` 零命中） | **不可见**——自举的失败在状态文件里，不在流里 |
| 终端直跑脚本、CI 跑脚本 | ❌ | **不可见**（无网关介入） |

**「证据分裂」的实际形态（实测）**：`.cycles/self-bootstrap.json` 记录了 round 1/2 两次失败
（`2026-10-18T15:35:13Z` / `15:39:08Z`），但 `flow-tracker.json` 在**同一时段零条记录**——
不是数据损坏，是**取证面缺位**。排障时不要因为「flow-tracker 没有」就断定「没跑过」。

> 修复方向（skill-eco P0）：self 端点接 `startFlow/finishFlow` 或改走统一网关。
> 验收判据：`/anic/self/iterate` 后 flow-tracker ≥2 条（eval/gate）。

## 5. 技能健康：成功率怎么算、为什么会「永远标红」

实现：`src/host/runtime/continuousLearning.ts`。

| 维度 | 语义 |
|---|---|
| `total` / `successRate` | **全史**计数（`done` / 总调用） |
| `recentSuccessRate` | **近期窗**：先按 `RECENT_MAX_AGE_MS`（**7 天**，`:36`）过滤，再**按 `startedAt` 升序排序**，最后 `slice(-8)` |
| `level` | `slow`（超时率优先）→ `degraded`（成功率）→ `insufficient`（窗内样本不足）→ 正常 |
| 三态 `recentSuccessRate` | `number` = 近期值；`null` = 近 7 天无网关调用；字段缺省 = 旧宿主（回落全史，零回归面） |

**两处必须知道的结构细节**：

1. **排序先于截断**——FlowTracker 的**追加序 ≠ 时间序**（跨天多轮交错写入），
   直接 `slice(-8)` 会取到「最晚追加」而非「最近发生」（cycle-57 已修，有回归钉）。
2. **时间窗空 → `insufficient`**，不是 `degraded`——「当前状态不可判定」与「当前状态是坏」
   是两回事。`insufficient` 也**不生成改进建议**（无近期数据 ≠ 当前故障；历史欠账归 tech-debt 队列管）。

### 5.1 「修复从未被健康面承认」（本仓真实案例，cycle-57 收口）

现象：`workflow-state` 连续多轮显示 **0% / degraded**，但账本与调研都表明脚本本身没坏。
根因链（**三层叠加**）：

1. **历史残留**：3 条失败全在 `2026-10-18`，均为「args 误带项目目录 → 位置参数数量不符」
   （cycle-38 前 6 连失败的同一根因）。
2. **修复后无新调用**：cycle-38 已修 `workspaceRedirect`，此后该脚本**再未经网关调用**——
   计数窗里的旧失败**出不去**（计数窗只在有新调用时才滑动）。
3. **时间窗终会放它出窗**：`RECENT_MAX_AGE_MS` 会把 7 天前的失败移出近期窗，
   届时自动转 `insufficient`（⚪「样本不足」）——这是**正确行为，不是面板 Bug**。

**面板上的正确读法**：`degraded` + 全史/近期双量纲 ⇒ 看**近期**值；若近期值来自 >3 天前的失败，
它仍如实展示（7 天朴素语义——**不按当日面板表现调参洗白**）。

### 5.2 `recentSuccessRate: null` 与 `◦7d` 徽标

- 路由把 `undefined` 显式转 `null`（JSON 序列化会丢弃 `undefined`，三态必须可辨）。
- 面板 `◦7d` 徽标（`data-anic-skill-health-stale`）= 「近 7 天无网关调用」的**可视化**——
  看到它意味着**这个数字不是当前的**，而不是脚本坏了。

## 6. L4 自举的真机现状（诚实披露）

**能力就位 ≠ 真机收敛**——这两件事在本仓必须分开陈述。

| | 结论 | 证据 |
|---|---|---|
| 能力就位 | 编排器全链（eval→gate→fix→**re-gate 复检**）已实现；表驱动中间态落盘；R-31 写侧隔离 | `bootstrapOrchestrator.ts`、`bootstrapSteps.ts` |
| **真机收敛** | **从未发生过一次**——`self-bootstrap.json` 两轮 `lastEvalScore: 0` / `lastGateVerdict: FAIL`；`CONVERGED` 恒假 | `.cycles/self-bootstrap.json`、`.cycles/tech-debt/self-bootstrap-round-{1,2}.json` |

**诊断（skill-eco 研究，附证据链）**：两轮 0 分**不是解析器坏了**（`scriptParsers` 已按真实契约
重写且有 22 例覆盖），而是 **「缺 cycle 前置」被折叠成了质量失败**——`eval-runner` 在缺
`.cycles` 配置时硬 `exit(1)`（`eval-runner.mjs:98`），插件把它记为 `evalScore 0`，
于是自举**在缺前置与真失败之间无法区分**，永远收敛不了，还产出误导性提案。

> 修复方向（P0）：缺前置时返回**专用前置错误**（或自动 `init-cycle`），不得计为 0 分。
> 见 §7 的验收判据。

## 7. 排障手册

| 症状 | 先查 | 判读 |
|---|---|---|
| 自举不收敛 | `.cycles/self-bootstrap.json` 的 `status`/`round` | `EVALUATING` 且 `lastEvalScore: 0` → 查是否**缺 `.cycles/cycles/cycle-N/` 前置**（§6） |
| 自举「跑了但 flow-tracker 没有」 | §4 取证面 | self 端点**本就不记账**——看状态文件，不是看 flow-tracker |
| 技能健康标红但脚本没坏 | `recentSuccessRate` 的样本时刻 + `lastInvoked` | 近期值来自 >3 天前 → 等待出窗转 `insufficient`；或**经 `anic_skill` 网关重跑一次**让新数据进窗 |
| `◦7d` 徽标 | §5.2 | 「近 7 天无网关调用」——数字非当前，非故障 |
| 债务队列有提案但健康面不红 | 两者是**两条通道**（§1） | health 提案落盘后健康面恢复不会自动 `resolved`；`resolved` 是**人的裁决**（带 `consumedBy`） |
| H3 门禁「缺门」但账本明明有 | `evaluateH3` 的 **per-gate-latest** 语义 | gate-check 对 result+detail 全同的门**去重不重录**；旧「末 4 条窗口」会误熔断（已改每门取最新） |
