# 工程脚本与场地自洽

> 本册覆盖 `dsh-anic/scripts/` 下 5 个**开发侧脚本**（非插件运行时代码）的职责、参数解析序，以及 cycle-43 的两项根因修复：**场地自洽化**（快照默认数据源切回本仓）与 **init-cycle ↔ workflow-state 联动**（技能状态机漂移根因）。技能脚本本体（`assets/skill/scripts/`）的接口参考见 `assets/skill/SKILL.md`。

## 2. 场地自洽化（cycle-43 T-4301）

### 2.1 背景与用户红线

用户红线：**dsh-anic 不得与 dsh-codegraph-visualizer 绑定**——后者只是验证测试场地。审计发现 `src/` 源码零硬编码场地路径（仅注释提及），耦合全部集中在三个脚本的**默认值**：

- `generate-snapshot.mjs`：`WORKSPACE` 默认 `join(PLUGIN_ROOT, '..', 'dsh-codegraph-visualizer')`——嵌入快照装的是**别仓**数据。
- `start-dsh-test.mjs`：`resolveWorkspace()` 默认解析到场地仓——测试宿主 cwd 落在场地。
- `j0-probe.mjs`：`TOOLCHAIN_ROOTS` 含场地仓兜底（借 playwright）。

### 2.2 裁决与实现

三项默认全部切回 `PLUGIN_ROOT`（本仓），语义从「可视化场地项目」改为「**自举：插件可视化自己的迭代历程**」：

| 脚本 | 变更 | 覆盖通道（保留） |
| --- | --- | --- |
| `generate-snapshot.mjs` | `WORKSPACE` 默认 `PLUGIN_ROOT` | `--workspace <dir>` / `DSH_ANIC_TEST_WORKSPACE` |
| `start-dsh-test.mjs` | `resolveWorkspace()` 默认 `PLUGIN_ROOT` | 同上（解析序：参数 > env > 默认） |
| `j0-probe.mjs` | `TOOLCHAIN_ROOTS` 移除场地仓条目 | `PLUGIN_ROOT` + `DSH_ANIC_TEST_WORKSPACE`（playwright 借用是 TD-A1 式过渡，非数据耦合） |

### 2.3 自洽快照的数据面证据

切默认后重建：`buildWorkflowSnapshot('./.cycles')` → **nodes 188 / edges 292 / cycles 43 / ledgerEntries 122 / incidents 0 / autonomy L2**——本仓 43 个循环的自身数据足以支撑自洽快照，无需场地数据。

### 2.4 连带契约修复（改 snapshotCore 要同步两处）

嵌入快照与路由快照**共用唯一构建器**（`src/shared/snapshotCore.ts`）。cycle-38 W-3 给 `SnapshotNode` 加 `detail`/`testReport` 字段时，`generate-snapshot.mjs` 模板里的 `WorkflowNode` 接口没同步——场地数据无 detail 字段故一直未暴露；切本仓数据后 gate-event 节点携带 detail，typecheck 立即报 TS2353。**教训：改 snapshotCore 类型，两处接口（路由类型 + 生成器模板类型）必须同改**。已在生成器模板补 `detail?: string` 与 `testReport?: {...}` 并注明同步契约。

测试侧连带：`tests/unit/zeroCoverageFiles.test.ts:189` 嵌入快照契约原钉 `autonomy === 'L4'`（场地数据面值）→ 放宽为合法自主级枚举 `['L1','L2','L3','L4']`（本仓真实 L2；autonomy 由工作区 `.cycles/config.yml` 判定，不该被测试钉死）。

## 3. init-cycle ↔ workflow-state 联动（cycle-43 T-4302）

### 3.1 漂移根因

- `init-cycle.mjs` 只 scaffold 目录 + 拷模板，**不写** `.cycles/workflow-state.json`；
- `workflow-state.mjs` 的 `initState` **仅在状态文件不存在时**才重建（数值序取最新循环）；
- 两脚本各管半边 → 本仓 cycle-27..41 期间直建目录，状态机 `currentCycle` 漂移停在 **cycle-26**（面板「流程状态机」分区显示旧循环的来源）。

### 3.2 修复设计（`syncWorkflowState`，三条防御线）

`init-cycle.mjs` 的 `scaffoldCycle` 尾部新增调用：

1. **损坏防御**：状态文件 JSON 解析失败 → 走重建（原子写守护在 `fs-safe.mjs`）；
2. **防回拉**：仅当新号 > 旧号才前移 `currentCycle`（数值序兜底——`--cycle` 传旧号不动状态机）；
3. **同号幂等**：已指向本循环 → 状态文件字节不动（updatedAt 不变）。

原子写用 `atomicWriteFileSync`；状态形状与 `workflow-state.mjs` 的 `initState` 同一（`currentPhase`/`currentCycle`/`phaseHistory`/`nodeStatus`/`createdAt`/`updatedAt` 六键）。

### 3.3 契约测试

`tests/unit/initCycleStateSync.test.ts`（7 用例，对安装副本黑盒 `execFileSync` 驱动）：前移 / 同号幂等 / 旧号防回拉 / 损坏重建 / 全新 initState 形状 / 标准键集 / 写盘存在性。

### 3.4 版本留痕

技能 CHANGELOG `2.5.0`；SKILL.md 快速启动第 7 步补 v2.5.0 注记（init-cycle 现同步推进状态机）。发行源（`assets/skill/`）与安装副本（`.dsh/skills/`）经手工 cp + 完整性守卫保持逐字节相同。

## 4. 通道声明机制：声明 ≠ 豁免，未声明即棘轮红（cycle-78 · WS-D）

### 4.1 被修的缺口

闭环三态矩阵把 routes 族算成 `63 注册 / 17 代码消费 / 46 未消费`。那 46 条**不是死代码**，
而是**通道独占**路由——消费方在 DSH 宿主 agent、外部 `curl`、运维脚本或 MCP 客户端，
本仓源码里根本没有调用点。问题在**机器视角**：`evidenceKind='none'` 的项被平铺进未消费
清单，面板只能说「46 条未消费」，人分不清哪条是「已声明的运维通道」、哪条是
「忘了接线的真缺口」——两种东西的**处置动作相反**（前者维持并复核文档，后者补接线）。

### 4.2 声明 = 谁维护 + 哪份文档 + 为什么

`src/host/closureAudit/channelRegistry.ts` 的 `CHANNEL_DECLARATIONS` 是唯一真相源，
每条声明是四元组：

| 字段 | 机器校验 | 为什么必须有 |
| --- | --- | --- |
| `route` | 必须与注册面逐字相等 | 拼错 = 声明落空（会显示成漏声明） |
| `owner` | 非空 | 没有责任人 = 实质豁免 |
| `docRef` | `docs/agents/<文件>#<路由>`：文件在扫描集 + 锚点命中**真实标题** + 该章节正文含路由字面量 | 「指向某份文档」是最容易伪造的证据，必须机器复核 |
| `reason` | 非空 | 没有理由 = 没解释，等于没说 |

**关键语义：声明不改变事实。** 带声明的项仍然 `consumed=false`、仍然计入 `unconsumed`，
只是从「未知缺口」（`consumedGap`/`producedGap`）搬到「已知通道」（`declaredChannel`）。
面板因此能把「46 条未消费」拆成「通道声明 46 / 未声明 0」——这正是白盒要的那一柄。

### 4.3 未声明棘轮（新增路由不声明即红）

`tests/contract/closureAuditContract.test.ts` 的 ③④ 与
`tests/contract/objectiveConformanceContract.test.ts` 的 ⑬ 机械断言：

1. 每条未消费路由都必须有声明（缺一条 ⇒ 测试红并**点名**该路由）；
2. 声明表不得指向注册面不存在的路由（幽灵声明 ⇒ 红）；
3. 每条声明的 `docRef` 必须能追到真实文档章节且该章节提到该路由（否则 ⇒ 红）；
4. 反向自检：内存副本删一条声明 ⇒ ①必红；篡改 `docRef` 锚点 ⇒ ③必红 —— 证明判据不是恒真。

`registryClosure.ts` 同时把校验结论写进 `notes`（`46/46 条有据` / `未声明未消费路由：N 条`），
**不静默**；但运行期不抛错——抛错会让整个面板失去数据，可见的缺口优于隐身。
判定红留在契约测试里（红了必须补声明或补消费方，而不是改断言）。

维护纪律：**只增不删**。路由接上真消费方后声明可保留（bucket 自然转为 `code`）；
不得为了变绿而删声明——删一条等于把该路由扔回「未知缺口」。

## 5. 部署一致性（cycle-80）：src 比 dist 新 ⇒ 契约红

**被守卫的缺陷**：本插件以 `link:` 安装在宿主 profile 里 ⇒ 宿主加载的**就是**
`dist/host.js` + `dist/client.js`。而开发流程是「改 `src/` → 离线金字塔全绿 → 忘了 build」：
测试直接 import TS 源码，宿主跑旧 bundle。于是"本轮已修好"在真机上完全不成立，
且没有任何断言会红——这不是环境差异，是**部署一致性零守卫**。

| 判据 | 机器断言（`tests/contract/deployFreshnessContract.test.ts`） |
| --- | --- |
| revision 形状 | `computeBuildRevision()` → `revision` 16 位 hex、`host`/`client` 各 64 位 sha256、`builtAt` 可解析 |
| 真实仓库必须新鲜 | `buildFreshness(pluginRoot).stale === false`（`newestSrc` mtime ≤ dist 构建时间） |
| 反向自检 | tmp 夹具：dist 新 → fresh；再造一个更新的 `src/*.ts` → **必须** stale（证明判定真看 mtime） |
| 失败方向诚实 | dist 缺失 → `stale === true` + `reason` 非空 + `revision === null`（缺文件不得报"新鲜"） |

口径：`stale = newestSrc > builtAt`，`builtAt` 取 `dist/host.js` 与 `dist/client.js` 的较新 mtime；
`revision = sha256(host + ":" + client).slice(0,16)`。

**纪律：`anic_reload_self` / `POST /anic/api/reload` 之前必先 build。**

- 热重载只负责"把宿主里的插件实例换成当前 `dist`"，它**不构建**：运行时里跑 tsdown
  会引入构建依赖，并撞上 `build-client.mjs` 的 F-09 删窗（先删 dist 再构建，失败即整目录消失）。
- 因此 `reloadSelf` 在 `stale === true` 时**拒绝**（`action:'refused'`），只有 `force:true`
  才跳过（仅测试/演示）。
- 冷启动时插件**只记录不重建**：`org-status.reload.stale` 与面板「构建与重载」小节把
  stale 事实暴露给用户（警示色），重建由人显式完成。
- 观测面：`org-status.reload`（`stale`/`revision`/`historyCount`/`lastStatus`/`lastAt`/`error`），
  重载史落 `.cycles/reload-history.json`；in-flight 记录在**触发重载之前**落盘，
  新实例启动时由 `finalizeInFlight` 改成 `reloaded`——这是"上次重载成没成"的唯一闭环证据。
