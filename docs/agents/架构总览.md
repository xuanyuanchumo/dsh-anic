# dsh-anic 架构总览

> 本文描述 dsh-anic 插件**实际存在的**模块布局与依赖方向。所有结论均来自源码阅读，行号为写作时的真实行号。
> 读取本文件的时机：新增模块、判断一段逻辑该放哪个目录、或需要确认某条依赖是否合法时。

## 1. 双入口与隔离规则

dsh-anic 是一个 DSH 插件，同时导出宿主半部与客户端半部（`package.json` 的 `exports`）：

| 入口 | 文件 | `name` | `inject` |
| --- | --- | --- | --- |
| 宿主 | `src/index.ts:16` `apply(ctx)` | `'dsh-anic'`（`src/index.ts:13`） | `['tools','webServer','sessions']`（`src/index.ts:14`） |
| 客户端 | `src/client/index.ts:16` `apply(ctx)` | `'dsh-anic-client'`（`src/client/index.ts:13`） | `['slots']`（`src/client/index.ts:14`） |

宿主入口 `apply` 用 `ctx.effect()` 承接四个注册器（`src/index.ts:38-42`：runtime skill / routes / tools / builtin flows），`registerAnicRoutes`（`src/host/routes/index.ts:54`）与 `registerAnicTools`（`src/host/tools.ts`）是主体。宿主无 `webServer` 时路由整体跳过，插件主体不受影响。

### 隔离由 `lib` 与 `include` 双重保证

两个 tsconfig 各自独立、**不 extends 任何根配置**（host 17 行 / client 18 行）：

- `tsconfig.host.json`：`lib: ["ES2022"]`，**无 DOM**；`include: ["src/index.ts"]` —— 宿主半部按**可达性**从单一入口编译，不是目录 glob。
- `tsconfig.client.json`：`lib: ["ES2022","DOM","DOM.Iterable"]`；`include: ["src/client/**/*.ts","src/client/**/*.tsx"]` —— 目录 glob，构造上**永远到不了** `src/host/`。

因此「宿主不能碰 `document`」不是纪律而是编译错误（DOM 不在 lib 里）；「客户端不能 import 宿主」同样由 glob 边界保证。两者共同启用 `allowImportingTsExtensions: true` + `noEmit: true`，这是 import 里写 `.ts` 扩展名合法的原因；`noUncheckedIndexedAccess: true` 是代码里大量 `?.` 与 `!` 的真实来源。

### 依赖方向（单向）

```
src/index.ts (host entry)          src/client/index.ts (client entry)
      │                                    │
      ▼                                    ▼
src/host/routes/*  ──┐              src/client/integrations/*
src/host/tools*.ts ──┤                     │
src/host/{runtime,evolution,governance,llm}/│
src/host/{logger,config,agents,skillInvoker,i18n}.ts
      │                                    │
      └──────────────► src/shared/* ◄──────┘
                    src/adapters/*
```

`src/shared/` 是**唯一**双向共享层，且必须是纯函数或无 DOM 假设的代码 —— `src/shared/flows.ts:10-11` 明确记录「本模块不接触 window/localStorage，存储读取在 client 集成层完成」。`src/shared/errors.ts:2` 声明为 client/host 共用单实现。

### 2.1 `src/host/routes/` — HTTP 面（按端点拆文件）

聚合器 `src/host/routes/index.ts:54` `registerAnicRoutes(ctx, options)` 是**纯组合层**（130 行），头部 `index.ts:4-13` 分区注释声明六域，实际注册覆盖**九个分区**（data/cycle/review/evolution/governance/self/native/dual + flows）：

| 域 | 路由模块 | 聚合位置 |
| --- | --- | --- |
| data | `snapshotRoute.ts`（根级 `src/host/` 下）/ `stepTraceRoute.ts` / `selfCheckRoute.ts` / `selfInitRoute.ts` / `invocationRoute.ts` | `index.ts:64-69` |
| cycle | `cycleRoute.ts` / `ledgerRoute.ts` / `stackProbeRoute.ts` / `segmentedLedgerRoute.ts` | `index.ts:74-77` |
| review | `reviewRoute.ts`（条件性 LLM） | `index.ts:84-93` |
| evolution | `evolutionRoute.ts` | `index.ts:94` |
| governance | `governanceRoute.ts` | `index.ts:98` |
| self | `selfBootstrapRoute.ts` / `skillRoute.ts` / `skillInstallRoute.ts` / `skillHealthRoute.ts` | `index.ts:101-106` |
| native | `nativeRoute.ts`（7 脚本原生等价物） | `index.ts:112` |
| dual | `dualBootstrapRoute.ts` / `truthAuditRoute.ts` | `index.ts:120-121` |
| flows | `flowsRoute.ts`（5 流程状态机 HTTP 面） | `index.ts:125` |

共享依赖经 `src/host/routes/routeContext.ts` 的 `buildRouteContext(ctx)` 提取（单一职责），产出 `{ send, getWorkspaceRoot, loadFlows }`。`SendFn` 类型定义在 `routeContext.ts` 并由 `index.ts:35` 再导出。

`src/host/snapshotRoute.ts` 是 data 域的**形状权威**：`SNAPSHOT_ROUTE`（`snapshotRoute.ts:28`）、`SnapshotCtx` 接口（`snapshotRoute.ts:34`）、`resolveWorkspaceRoots(ctx, req?)`（`snapshotRoute.ts:58`）、`sendJson(res, status, body, extraHeaders)`（`snapshotRoute.ts:120`）都定义于此，其余路由模块复用同一份窄化，不各自发明。`resolveWorkspaceRoots` 的多会话解析顺序（claimed 头 → knownRoots → `.cycles` 探测 → registry → sessions → cwd）见 cycle-21/22 的工作区解析收口。

**disposer 纪律**：每个路由注册都返回 `(() => void) | null`，聚合器在 `index.ts:127-129` 过滤出函数并返回一个统一 cleanup：

```ts
const cleanups = disposers.filter((d): d is () => void => typeof d === 'function');
if (cleanups.length === 0) return null;
return () => { for (const d of cleanups) d(); };
```

被 `tests/contract/dshConformance.test.ts`（disposer 形状断言段）以源码形状守卫钉死（要求 `typeof d === 'function'` 与 `for (const d of cleanups) d()` 两个形状同时在）。

### 数据热更新三层（`WorkflowGraphPanel.ts:7-10`）

1. 嵌入快照（构建期生成，永远可用——多代宿主安全底线）；
2. live 路由 `GET /anic/api/workflow-snapshot`（挂载时与点「刷新」时拉取）；
3. 路由缺失/404/5xx/无 fetch → 回退嵌入快照，底行**如实显示来源**。

`fetchLive` 的后继 `components/usePanelFetch.ts`（`usePanelFetch` hook）统一防抖/降级/学头机制：一次性任务集（snapshot / step-trace / self-check，`panelLiveTargets.ts` 工厂）与 4s 轮询任务集（org-status / flows-status / cycle list+state / ledger list+verify / hitl-audit / skill-health / governance-budget，治理证据簇 + 技能健康）并发拉取，各自独立降级、各自拒绝畸形形状；实时调用流（`useInvocations`）单独 2s 档。invocations 分区在有 turn 元数据时按 turn 折叠分组（`details/summary` 原生折叠，最新组默认展开，cycle-20 P2）。账本分页（cycle-24 P3）：`governanceTargets(setters, ledgerLimit)` 按翻页深度拉取，「显示更多」抬 limit+24 并触发重拉（`renderLedger` 第三参 actions 契约）。
