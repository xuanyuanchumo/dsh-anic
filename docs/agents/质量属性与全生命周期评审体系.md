# 质量属性与全生命周期评审体系

> dsh-anic 的质量模型：功能面（E/Q 维度）× 非功能面（质量属性）× 生命周期门禁（G0-G3 + 人类门）三层互锁。
> 本文档是该体系的单一权威描述，替代散落在 docs/anic 各篇的局部定义。

## 1. 评估维度与质量评审（E1-E8 / Q1-Q8）

E1-E8 是**评估**维度（项目当前状态好不好），Q1-Q8 是**质量评审**维度（交付物质量过不过）。两者都来自技能 `eval-runner.mjs` 的既定分派：

| 维度 | 名称 | 检查方式 | dsh-anic 对应 |
|---|---|---|---|
| E1 | 意图对齐 | 检查 intent 工件 | `gateEvidence.collectGateEvidence` intent 证据 |
| E2 | 规格符合 | 规格↔实现抽查 | truthAudit T1-T4 |
| E3 | 测试结果 | test-report 解析 | `tests/` 三层金字塔 |
| E4 | 静态检查 | lint/validate | `pnpm run lint`（validate-dsh.mjs C1-C12） |
| E5 | 性能基线 | 需基线工件 | 技能侧恒 SKIP（已知缺陷，勿复制） |
| E6 | 安全 | 密钥/依赖检查 | CORS 白名单、env 清洗（进行中） |
| E7 | 文档同步 | 文档↔代码抽查 | 本文档族 + truthAudit 文档漂移守卫 |
| E8 | 综合测试 | 同 E3 源 | — |
| Q1 | 意图质量 | 同 E1 | — |
| Q2 | 测试零错 | test-report 表格契约 | `| 通过 |` 行解析 |
| Q3 | 构建成功 | build_cmd 执行 | `node scripts/build-client.mjs` |
| Q4 | 安全三合一 | 安全+硬编码密钥+依赖审计 | — |
| Q5 | 架构分层 | 层间依赖/循环检查 | typecheck 双编译单元 + G-IND |
| Q6 | 体验三合一 | a11y + i18n + 响应式 | contrastContract / clientI18n / panelCss |
| Q7 | 工程三合一 | lint + 复杂度 + 错误处理 | T3 250 行守卫 |
| Q8 | 交付完整 | 交付清单+评审证据 | 四件套 |

三态合并律（`eval-runner.mjs:46-51`）：任一 FAIL ⇒ FAIL；无 FAIL 有 SKIP ⇒ SKIP；否则 PASS。退出码只由 FAIL 决定。

## 2. 生命周期门禁（G0-G3）

宏观循环 Plan→Design→Build→Test→Deploy→Maintain，各阶段收敛门：

| 门 | 名称 | 判据（机械可验） | 通过条件 |
|---|---|---|---|
| G0 | 评估收敛门 | Q1（意图质量）+ Q5（架构分层） | 两维 PASS |
| G1 | 任务收敛门 | Q7（工程三合一）+ 任务清单清零 | 无未完成任务行 |
| G2 | 测试收敛门 | Q2（测试零错） | 测试全绿 |
| G3 | 构建交付门 | Q3（构建）+ Q4（安全） | 构建成功 |

- `--record` 模式：结果写入 `.cycles/gates/ledger.json`（哈希链账本，canonical 六字段键序，INV-20）。
- **门禁事件 ≠ 人类门事件**：H1-H4（HITL 审计检查点）与 G0-G3 分属两载体；人类门是唯一不可跳过的判断点（宪法：任何进化含 L4 不得移除）。
- 门名体系分离：ANIC 人类审批门 `intent/spec/plan/pr/release`（multiAgentGate，阈值 2/2/2/3/3）vs 收敛门 `G0-G3`（gate-check）。**两套门名没有隐式映射**；pr/release 门的收敛证据经 `gateEvidence.ts` 的 `CONVERGENCE_GATES = ['G0','G1','G2','G3']` 显式装配。

## 3. 非功能质量属性（本插件的工程承诺）

### 3.1 性能
- 快照构建 O(n)（snapshotCore，原 O(n²) 已修）；状态机转移 O(1)（buildGraphIndex 索引，原 O(n) find）；
- 分段账本 append O(1)（head.json + seg-NNNNNN.jsonl 只追加，1000 条/段）；
- 实时调用环回缓冲 drop-oldest（limit 50），快照零副作用。

### 3.2 安全
- CORS 默认拒绝显式放行（`src/host/cors.ts`）：仅回环来源 + 显式配置集被回显具体 Origin；配置写 `*` 不重新打开通配符；绝不返回 `*`（P0-8 已修+17 用例守卫）；
- 诊断域隔离 INV-26：插件错误永不写 `.cycles/incidents/`；
- write-then-rename 原子写（`shared/fs-safe.ts`）；
- 已知债务：`src/adapters/index.ts` 的 `spawnSync` env 清洗（丢 `*KEY*/*SECRET*/*TOKEN*/*PASSWORD*`）待接线（KB R19）。

### 3.3 可用性 / 无障碍
- 对比度契约 `tests/contract/contrastContract.test.ts`：全令牌穷举四类分类（TEXT_ROLES/NON_TEXT_ROLES/DECORATIVE/SPECIAL），新增令牌必须登记（穷举断言强制）；
- `aria-live='polite'` 状态播报（工具栏 + 自举四态反馈）；
- 已知债务：169 图节点全 `tabIndex=0`（应 roving tabindex）、SVG 无 role/aria-label/desc（P1-2/3）。

### 3.4 国际化
- host 侧 `t()`（`src/host/i18n.ts`）+ client 侧 `t()`（`src/client/i18n.ts`，零依赖 JSON import，回退链 当前语言→zh→键名）；`'ANIC'` 标签名是品牌名不翻译。

### 3.5 可维护性
- 单文件 ≤250 行（T3 守卫真实拦人：曾拦 303 行 reviewEngine 与 253 行面板，拆分而非放宽）；
- 一域一文件 / 路由按端点拆 / 特性模块制（`features/<域>/<模块>.ts`）；
- G-IND 独立性守卫（源码不得 import 父项目 src/）；
- typecheck 覆盖守卫（每个 src 文件恰好落一个 tsconfig，`tests/contract/typecheckCoverage.test.ts`，含证伪演练记录）。

### 3.6 可靠性
- 四域错误码 `ANIC_{ROUTE|FETCH|RENDER|CONFIG}_*`；
- fail-closed 家族：评审 JSON 校验失败→doubt；技能 frontmatter 解析失败→跳过注册；账本 JSON 损坏→空 Map 不 throw；
- 「没有证据 ≠ 通过」：doubt 三态贯穿门禁与评审。

## 4. 测试金字塔（五层）

| 层 | 载体 | 内容 |
|---|---|---|
| L1 规范门 | `validate-dsh.mjs` | DSH 规范符合性 C1-C12 |
| L2 单元 | `tests/unit/`（vitest） | 纯函数与模块行为 |
| L3 契约守卫 | `tests/contract/` | 跨模块形状/纪律（对比度、独立性、typecheck 覆盖、面板布局、工具输出、客户端渲染、DSH 符合性） |
| L4 机制冒烟 | `offline-smoke.mjs`（stub 宿主） | 19 项端到端机制断言（读 dist，先 build 再跑） |
| L5 真实宿主 | `j0-probe.mjs` / start-dsh-test.mjs + Chrome DevTools | CDP 六判据（绝不启停宿主） |

> **用例与文件计数不在本册写死**——测试面每轮增长（v0.17.0 时点为 71 文件 863 用例，见当轮 `.cycles/cycles/cycle-N/test-reports/test-report.md`）。**以 `node scripts/run-tests.mjs` 实时输出为准**。

## 5. 每轮交付纪律（四件套）

每个迭代轮次产出并过 G0-G3：
1. **项目评估报告**（E/Q 维度裁决 + 证据）；
2. **任务清单**（P0-P3 分级，含完成状态）；
3. **测试报告**（五层金字塔结果 + 真实宿主旅程记录）；
4. **交付清单**（文件级变更 + 破坏性变更 + 已知债务）。

落盘位置：`.cycles/cycles/cycle-N/`（模板复用技能 `assets/templates/`）。
