## 0. 为什么要有这一轮（实测缺口，全部可复现）

上一轮（cycle-72..74）交付了「注册↔生产↔消费」闭环体检，但它**自述可信度不足**。
本册开头的数字全部由 Lead 在 cycle-75 起点实测（命令见 §5）：

### 0.1 路由族：双向误差（**最严重**）

| 现象 | 实测 | 判定 |
|---|---|---|
| 扫描器报「注册 63 条 | `/anic/` 字面量在路由文件里的出现次数（含 JSDoc 头注、错误消息、响应字段） |
| 真实 `webServer.register({path})` 注册点 | **53 条**（`grep -c "path: '"` 计 16 → 实为 53 个 register 调用）| — |
| **幽灵注册**（扫描器报注册、代码里根本没有） | **10 条**（`/anic/api/trust`、`/anic/flows`、`/anic/flows/status`、`/anic/api/tech-debt/list` 等） | ❌ 硬缺陷：把**注释/文档/错误文本**当成注册 |
| **漏报注册**（真实注册、扫描器没看见） | `/anic/api/workflow-snapshot`、`/anic/api/step-trace`、`/anic/api/self-check`、`/anic/self/init`、`/anic/api/closure-audit` 等 | ❌ 硬缺陷：`registerXxxRoute` 形态的可配置路径未覆盖 |
| `produced`（`routeWired` 只看 `routes/index.ts` 是否含 id 子串） | 63 报 1 | ❌ 硬缺陷：注册在**路由文件内部**完成，`index.ts` 只调用注册器 ⇒ produced 恒 1 |
| `unconsumed` 路由 | 44（其中 10 条是幽灵） | 虚高 |

**结论**：路由族的 registered / produced / unconsumed 三个数**没有一个可信**。

### 0.2 词表族（i18n）：假阳性 + 不可达分支

> **⚠️ 本段口径已被 cycle-75 实测推翻并修正（T2 交付 + Lead 独立复核）。**
> 原文写的「真实值 45 / 被降到 42」是**反的**。A/B 实测（同一文件集，只替换
> `dynamicKeyPrefixes` 实现）：
>
> ```
> OLD(HEAD) = 45 | NEW(修复后) = 42 | delta = 3
> gained (修复后转为已消费): budget.status_normal / _warn / _alert
> lost  (修复后转为未消费): []
> ```
>
> 落差 3 项**全部**由 `t(\`budget.status_${data.status}\`)` 真实消费
> （`src/client/features/budget/renderBudget.ts:122`，`data.status` 联合类型正是三值）。
> ⇒ **42 是真值；45 才是把三个真被消费的键误报成未消费的假阳性值。**
> **不得**「恢复 45」。

- **死分支（已确证并修复）**：原 `indexOf(BACKTICK + '${')` 搜「反引号紧接 `${`」——
  反引号在首位、`${` 在中段 ⇒ 模板分支**恒不命中**。实测最小样例：
  `HEAD branch hits = 0` → `FIXED = 1`。
- **`endsWithSeparator()` 放宽是正确的**，且契约原文担心的 `closure.cluster.` 假阳性
  **在本实现里不存在**：那三个键确已**字面量**消费（`renderClosure.ts` 的
  `CLUSTER_LABEL_KEYS`），走字面量路径、不依赖模板前缀。该前缀只在**不去注释**时
  才会被构造（`dynamicKeyPrefixes` 首行即 `stripComments`，故被挡住）。
- **新发现真实根因（契约原文未点名）**：`line.indexOf('t(')` **没有词法边界**——
  `agentCards.get(\`anic.agent.${gate}.${role}\`)` 的 `get(` 尾串被当成 i18n 调用，
  凭空造出 `anic.agent.` 前缀。今日认领 0 键故无害，但一旦新增 `anic.agent.*` 键，
  Map 查表就会被冒充成词表消费。同类尾串 `X.split('.')` 在 4 个文件里触发过。已修。
- **`assets/**` 判定为假消费并收窄**：技能脚本以**目标项目**目录为根探测词表
  （`eval-runner.mjs:363-365` 探测 `join(projectDir,'locale')` 等），不是本插件
  `locale/zh.json` 的读取方。与已冻结的 `routeConsumerUniverse` 口径统一。
  收窄计数影响**中性**：实测 0 个键依赖 assets/ 独证消费。
- **注释证据（判定纪律⑥）**：`collectRefs` 此前在原始文本上取证据 ⇒ evidence 会锚到
  注释行（实测 4 处）。已改为在 `stripComments` 文本上取（保留换行，行号仍与磁盘一致）。

### 0.3 produced 语义未经证据检验

`producedCount()` 对路由族只看 `routes/index.ts` 是否含 id 子串（见 0.1），对工具族看
「同文件有 `execute:`」。后者在 `tools*.ts` 拆分后仍成立，但**没有任何逐项证据**：
`ClosureItem.producedAt` 恒等于 `definedAt`，读者无法区分「注册了且有 handler」
与「只声明了名字」。**produced 必须带自己的证据锚点**。

### 0.4 未消费清单缺少「为什么」与分类

面板把 86 条未消费**平铺**，不区分：
- 「生产了但没人消费」= 真缺口；
- 「计算键已认领消费、只是没有字面量证据」= 假阳性；
- 「只有声明、没有接线」= 产出缺口；
- 「只有测试/agent 卡引用」= 通道级。

读者无法据此行动 ⇒ 白盒**形式上有、语义上是噪声**。

### 1.2 `assetClosure.ts`（writer: T1）——路由族真值

核心改动：注册点扫描必须**只看真注册调用**，且**双向**（报注册必须真有；真注册必须报）。

```ts
export interface RouteDef {
  id: string;
  /** 声明处 file:line；无则 null。 */
  declaredAt: string | null;
  /** 真注册调用点 file:line；无则 null（= 声明了但没接线）。 */
  producedAt: string | null;
}

/** 定义扫描：只认真注册调用里的 path 字面量（JSDoc / 错误消息 / 响应字段一律不算）。 */
export function scanRouteDefs(files: Map<string, string>): RouteDef[];

/** 真注册点判定（供 produced 证据）。 */
export function routeRegisterSites(files: Map<string, string>): Map<string, string[]>;
```

**注册形态白名单（必须全覆盖，缺一即漏报）**：

1. `c.webServer.register({ kind: 'exact', path: '/anic/...', handler })` — cycleRoute/ledgerRoute 等
2. `reg('/anic/...', handler)` 局部封装（`flowsRoute.ts` 的 `const reg = (path, handler) => ...`）
3. `registerRoute({ ..., path: '/anic/...' })` 自定义封装（`snapshotRoute.ts` 等）
4. `registerXxxRoute(ctx, { ... })` 注册器，其**内部**有上述 1-3 ⇒ 由 1-3 覆盖；
   注意 `routes/index.ts` 只是聚合器，**不是**生产点。

**判定纪律（承既有 ①②③④⑤，新增 ⑥⑦）**：
- ⑥ **去注释后**再扫（`stripComments`），且在去注释文本上定位；
- ⑦ 注册点必须同时命中「注册调用词」与「path 字面量」**同一行或同一次调用块**。

**消费面**（不变）：客户端 fetch 常量 / 宿主内部调用 / CLI 脚本；
`tests/`、`docs/`、`locale/`、`assets/`、`.json`、`.md` 不计消费。

### 1.4 `registryClosure.ts`（writer: T3）

```ts

```

> **恒等式（cycle-78 升级，不得放宽）**：
> `registered = code + dynamicClaimed + channelOnly + declaredChannel + consumedGap + producedGap`；
> `unconsumed = declaredChannel + consumedGap + producedGap`；
> `consumed = code + dynamicClaimed + channelOnly`。
> `clustersConsistent()` 逐族机械校验这两组成分恒等式（只校验总和会漏掉
> 「未消费项被算进已消费」这类方向错误）。

> **注**：`dynamic === true` 的项在既有实现里**必为 consumed**（evidence 非空）。
> 故第三类改为：**`dynamic && consumed` 但**无字面量证据**（`evidenceKind` 由动态判定给出）
> —— 这类是「已认领消费、证据是计算键」。分类必须**互斥且穷尽**未消费项，
> 实现者需先用实测确定分类判据并在代码里写死断言。
> 若实测发现 `dynamic && !consumed` 存在，则如实按该形态分类，不要削足适履。

## 6. 硬约束（全部工作项共同）

- **R-31 只读纪律**：闭环体检的**扫描器**永远不写工作区、不改源码；
- **G-IND 独立性守卫**：`src/` 不得 import 父工程 `src/`；
- **零行为变更默认**：`toolDisclosure` 默认 `full`；闭环体检是只读观测面；
- **一域一文件 / 单文件 ≤250 行**（vitest T3 会拦）；
- **i18n**：用户面文本一律 `t()`；**日志**：`scoped()` logger，不直连 `console`；
- **响亮失败**：无法评估记 `SKIP` 而非 `PASS`；空扫描集响亮抛错；
- **告警级守卫等于没有守卫** —— 本轮新增守卫一律**错误级**（exit 非零 / 断言红）。
