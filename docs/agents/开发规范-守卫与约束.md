## 4. 日志：`createScoped()`，`console` 只许在 `logger.ts` —— 测试强制

**权威模块**：`src/host/logger.ts`（71 行），**全项目唯一 `console` 落点**。

```ts
export function createScoped(scope: string): Logger   // logger.ts:44
export function setLoggerSink(sink: LoggerSink): void // logger.ts:40
export function newRequestId(): string                // logger.ts:67
export const consoleSink: LoggerSink = ...            // logger.ts:30
```

前缀形状：`${ANIC_LOG_PREFIX}[${scope}]`（`logger.ts:45`），`ANIC_LOG_PREFIX = '[dsh-anic]'`（`logger.ts:14`）。带 requestId 时追加 ` [rid]`（`logger.ts:47`）。三条消息分支（`logger.ts:48-56`）：

1. 对象且 `code` 是字符串 → `[${code}]` 段；
2. `Error` 实例 → `[UNCLASSIFIED]` 段；
3. 其余 → 直接拼消息。

**`consoleSink` 静默丢弃 `debug` 级**（`logger.ts:31`，注释「宿主控制台噪音治理」），因此 `log.debug()` 在当前 sink 下**没有输出** —— 调试时不要依赖它。

**`setLoggerSink` 是唯一的替换点**（`logger.ts:37-42`），`let activeSink` 模块级变量。测试用它注入 sink 捕获日志；业务代码不得调用。

### 守卫：`tests/contract/dshConformance.test.ts:183-215`

```ts
const SANCTIONED = SRC_FILES.filter((f) => f.endsWith(join('host', 'logger.ts')));
expect(SANCTIONED, '必须且只能有一个 logger 实现文件').toHaveLength(1);   // :192-193
// 其余文件出现 console.* → offenders
expect(offenders, 'console.* 必须集中到 host/logger.ts:\n' + offenders.join('\n')).toEqual([]);  // :202
// 防空转：被豁免的文件里必须真的有 console 引用
expect(consoleHits.length, 'logger.ts 的 consoleSink 必须真的调用 console').toBeGreaterThanOrEqual(3);  // :208
// 调用方纪律：不得直接引用 consoleSink
expect(readFileSync(f, 'utf8'), f).not.toMatch(/consoleSink/);   // :213
```

**这是「加强而非削弱」的范例**（`dshConformance.test.ts:186-191` 注释）：原断言是「`src/` 全域零 `console.*`」，那是 logger 落地**之前**的形态。logger 引入后，正确形状不是「零 console」而是「console 只准出现在这一个文件里」—— **后者比前者更强**，因为它同时禁止了新调用点绕过 Logger 直接打日志。改动这条守卫时不要退回「零 console」。

### 实际使用

`src/host/routes/nativeRoute.ts`（`createScoped('anic:route:native')`）、`selfCheckRoute.ts`（`anic:route:self-check`）、`selfInitRoute.ts`（`anic:route:self-init`）、`skillInstallRoute.ts`（`anic:route:skill-install`）。**客户端半部零日志调用**。

**INV-26 声明**（`logger.ts:10-11`）：「本模块只写日志流，**绝不写 `.cycles/`**」——注释称该不变量由 tests/contract 常驻守卫与 self-check 探针共同约束，但见 §8：**当前没有机械守卫检查这一条**。

## 5. i18n：用户面文本经 `t()` —— 仅文档约定（且实践未完全遵守）

**实现**：`src/host/i18n.ts`（44 行），`t(key, params?)`（`i18n.ts:36`）。

```ts
let val = lookup(zhDict, key) ?? lookup(enDict, key) ?? key;   // i18n.ts:37
```

三级回退：中文 → 英文 → key 本身。字典在模块加载时从 `join(__dirname, '..', '..', 'locale', '{zh,en}.json')` 读入（`i18n.ts:31-32`），**读失败静默降级为空对象**（`i18n.ts:33` 的 `catch`），此时所有 `t()` 返回 key。参数替换用 `new RegExp('\\{' + k + '\\}', 'g')`（`i18n.ts:40`）。

`locale/zh.json` 与 `locale/en.json` 各 258 行，19 个顶层域键：`meta`/`panel`/`flows`/`gate`/`presentation`/`review`/`org`/`state`/`trace`/`diag`/`prefs`/`cycles`/`ledger`/`hitl`/`gauge`/`health`/`live`/`budget`——扁平化后 **220 键**（两语言键集一致由 `dshConformance.test.ts:80` 守卫）。

### 实际使用（cycle-28 校准）

`t()` 调用点分布：**宿主 8 处**（`reviewRoute.ts:52/57/76` + `presentation.ts:115/135/143/152/160`，工具卡片用户面文本）+ **客户端 29 处**（`src/client/i18n.ts` 57 行的客户端字典装载是主消费面，覆盖全部特性域渲染器）。

客户端在 cycle-16~24 的 UI 域轮次中已全量接入 `t()`：分区标题、按钮、徽标、空态、aria-label 全走键引用（如 `panel.refresh`/`ledger.showMore`/`budget.barLabel`）。历史状态「客户端硬编码中文、panel.* 键无消费者」已收口。

**注意 JSON 重复键地雷**（cycle-20 事故教训）：`JSON.parse` 语义是 **last-wins**（后者覆盖前者），而 PowerShell `ConvertFrom-Json` 是 **FIRST-wins**——两工具对同一文件的视图可能不同。改 locale 必须用 node 脚本（`JSON.parse` 口径）读写，并用「键名在文件全文出现次数」复核无重复键。

### 唯一的机械检查

`tests/contract/dshConformance.test.ts:80` 检查 locale 形状：en/zh 都能 parse、`meta.title` 与 `meta.description` 非空、两者键集排序后相等（parity）。它**不检查**调用点是否用了 `t()`，也不检查是否有未使用的 key——这两条保持文档约定。

**为什么没有更强的守卫**：可以写「客户端源码不得出现中文字符串字面量」，但那会误伤注释（本工程注释全中文），需要完整的注释剥离 + 字符串字面量提取，成本远高于收益。

## 6. `cg-` / `anic-` CSS 前缀 —— 仅文档约定（且 `cg-` 在本工程不存在）

**实测结果（务必先读）**：

- **`cg-` 在 `dsh-anic` 全工程零命中** —— 对 `src/**`、`tests/**`、`scripts/**` 搜 `cg-` 得 0 条。`cg-` 是**父工程** `dsh-codegraph-visualizer` 的约定（见仓库根 `CLAUDE.md`），本插件不继承它。
- **本工程零 `className` 使用**，且**零 `.css` 文件**（`Get-ChildItem -Recurse -Include *.css` 无结果）。全部样式是 React `createElement` 的**内联 `style` 对象**。

因此本工程实际存在的「前缀」只有三类：

| 类别 | 前缀 | 实例 |
| --- | --- | --- |
| CSS 变量（令牌） | `--anic-*` | `--anic-pass` / `--anic-surface` / `--anic-border` 等 11 个（`src/shared/tokens.ts:45-57`） |
| DOM 数据属性（测试锚点） | `data-anic-*` | `data-anic-refresh`、`data-anic-prefs-toggle`、`data-anic-self-init`、`data-anic-toolbar`、`data-anic-workflow`、`data-anic-steptrace-wrap`、`data-anic-steptrace-disabled`、`data-anic-diagnostics-wrap`、`data-anic-diagnostics-disabled`、`data-anic-org-wrap`（共 10 个） |
| 元素 id | `anic-*` | `anic-design-tokens`（`WorkflowGraphPanel.ts:49`）、`anic-prefs-drawer`（`prefsDrawer.ts:54` 的 `PREFS_PANEL_ID`） |

**`data-anic-*` 是 smoke 测试的锚点**（`scripts/offline-smoke.mjs` 断言 `data-anic-refresh` 存在且唯一、三个 M1 动作齐备），改动这些属性名会同时打断 smoke。

**`--anic-*` 有真正的机械守卫**：`tests/contract/clientRenderContract.test.ts:140-151` 禁止任何文件（除 `tokens.ts` 自身）出现裸 `var(--anic-*)`。详见 [设计令牌与主题.md](设计令牌与主题.md)。

**没有守卫的部分**：`data-anic-*` 与元素 id 的命名规范没有任何测试检查；它们只被 smoke / J0 隐式依赖。

## 7. ESM `.ts` 扩展名 —— 运行时强制

**两个 tsconfig 都启用**（各 17 行，互不 `extends`）：

```json
"allowImportingTsExtensions": true,
"noEmit": true
```

`allowImportingTsExtensions` 是写 `.ts` 扩展名合法的前提（TypeScript 默认禁止），`noEmit` 是它的必要条件。因此 `import { x } from './y.ts'` 是本工程的标准形态。

**运行时也强制**：Node 的 ESM loader 要求显式扩展名（无 `.ts` 则解析失败），`scripts/offline-smoke.mjs` 用 `new Function('window','require', bundle)` 执行 client bundle，其 `require` 只解析 `react`，其余 import 已在构建期被 tsdown 内联。`package.json` 的 `"type": "module"`（`scripts/validate-dsh.mjs` 的 C1 检查项）是这一形态的根。

**没有专门的测试扫描 import 扩展名** —— 但写错会让 typecheck 或 build 直接失败，属于构建/运行时强制而非「仅文档约定」。

## 8. G-IND 独立性：源码不得 import 父项目 `src/` —— 测试强制（8 用例机械守卫）

**规范原文**（`dsh-anic/CLAUDE.md:31`）：「独立性守卫 G-IND：dsh-anic 源码不得 import 父项目 src/——只许借 node_modules」。

**守卫实现**：`tests/contract/independenceGuard.test.ts`（8 用例，机械守卫）。扫描 `src/`、`tests/`、`scripts/` 的 import 说明符，断言不得出现解析到父工程根的路径（`../../../src/`、`../../packages/` 等形态）；并遵守三条守卫纪律——① 反向自检（合成的违规样本必须被匹配器命中）；② 不匹配自身（样本用字符串拼接构造，扫描器看不到字面量）；③ 扫描集非空断言（防 glob 失手后 0 文件 = 恒过）。

**历史勘误（cycle-40 文档审计 P0-1）**：本节旧版声称「G-IND 无机械守卫、仅文档约定」并附「全目录只有 4 处散文命中」等三条实测证据——该结论**过时且颠倒**：守卫测试早已存在（CHANGELOG.md:969 曾记录「G-IND 过时表述修正」，但当时只修了 docs/agents/README.md:28，漏修本册与开发规范.md，造成同族三册互相矛盾——质量属性册当时已正确把 G-IND 列为守卫执行者）。当前全仓 `G-IND` 命中 42 处；`src/host/logger.ts:11` 与 `src/host/routes/selfCheckRoute.ts:105` 的「G-IND 常驻守卫」注释**成立**（即指上述守卫测试）。

**仍靠显式设计维持的部分**：`dsh-anic` 借用父工程 `node_modules` 是**过渡态 TD-A1**（`CLAUDE.md:3`）——「借 node_modules」被显式设计（`scripts/run-vitest.mjs` 与 `scripts/typecheck.mjs` 向上查父工程），守卫只拦「借源码」。

## 9. DSH 清单符合性 —— 测试强制 + 构建门

**两层执行者**：

1. **构建门** `scripts/validate-dsh.mjs`（155 行，`pnpm run lint` / `pnpm run validate:dsh`），12 项检查 C1–C12，任一 FAIL 即 `exit 1`（「响亮失败」），支持 `--json`。
2. **测试** `tests/contract/dshConformance.test.ts:52-90`（manifest 段）与 `:92-115`（dist 产物段）。

| 检查 | 内容 | 出处 |
| --- | --- | --- |
| C1 | `pkg.type === 'module'`（ESM-only 红线） | `validate-dsh.mjs` |
| C2 | `dsh.manifestVersion === 1` | 同上；`dshConformance.test.ts:53` |
| C3 | `dsh.client.platform === 'web'`（非 web 不加载客户端半部） | 同上；`dshConformance.test.ts:58` |
| C4 | 每个 `dsh.client.inject` 条目匹配 `/^@deepseek-ai\//`（第三方包 = 破坏性变更面） | 同上；`dshConformance.test.ts:62` |
| C5 | `exports['./client']` 是字符串且指向存在的文件（唯一客户端入口权威，缺失即宿主 throw） | 同上；`dshConformance.test.ts:68` |
| C6 | `exports['.']` / `['./package.json']` / `['./locale/*.json']` 都是字符串 | `validate-dsh.mjs` |
| C7 | locale en+zh 可 parse、`meta.title`/`meta.description` 非空、键集对齐 | 同上；`dshConformance.test.ts:80` |
| C8 | `icon` 存在、扩展名在白名单、≤ 256 KiB | 同上；`dshConformance.test.ts:74` |
| C9 | `dist/client.js` 存在、含 `__ModuleLoader__` + `.load(` + `factory`、`node --check` 通过 | 同上；`dshConformance.test.ts:93` |
| C10 | `dist/host.js` 存在、`node --check` 通过、动态 `import()` 得到 `apply` 函数 + 非空全字符串 `inject` + `name === 'dsh-anic'` | 同上；`dshConformance.test.ts:103` |
| C11 | 声明的 `dsh.bundle.patch` 文件存在 | `validate-dsh.mjs` |
| C12 | `README.md` 存在 | `validate-dsh.mjs` |

**C9 / C10 是「构建产物契约」而非源码契约** —— 它们读 `dist/`，所以对 `src/` 的修改**惰性**：必须先 `pnpm run build` 才能观察到变化。这条已在 `CLAUDE.md` 的「测试读 `dist/` 对 `src/` 变更惰性——先 build 再跑 smoke」记录。
