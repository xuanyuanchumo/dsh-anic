# dsh-anic 设计令牌与主题

> 本文件描述三层令牌体系（`palette.ts` 原语层 → `tokens.ts` 语义层 → 组件消费层）、注入机制、暗色适配与对比度契约，以及守卫面。
>
> 读取本文件的时机：新增颜色、新增内联样式、新增暗色适配，或判断某个颜色该不该走 `token()` 时。

## 1. 三文件体系（cycle-18 令牌代际校准后的现状）

| 文件 | 行数 | 职责 |
| --- | --- | --- |
| `src/shared/palette.ts` | 145 | **原语层**：64 个按角色命名的十六进制原语，全工程十六进制字面量的**唯一合法归宿** |
| `src/shared/tokens.ts` | 214 | **语义层**：`SEMANTIC` 42 键 + `SEMANTIC_DARK` 22 键暗色覆盖 + `token()`/`tokenCssBlock()` + `TOKEN_SCOPE` |
| `src/shared/shellTheme.ts` | 69 | 宿主主题探测：`HOST_DARK_ATTRIBUTE`（`data-ds-dark-theme`）观察、`resolveShellTheme`/`observeShellTheme`/`THEME_ATTRIBUTE` |

### 1.1 原语层：为什么是「按角色命名」而不是亮度档位

`palette.ts:2-15` 头部注释记录了改造动机：旧体系 `PALETTE.green500/green600/green700` 的档位名暗示亮度分档，但同一「PASS 绿」在 gate/status/text 三个角色里各取一档，与实际可读性毫无关系（`green600` 浅色面仅 3.15:1、`green500` 仅 2.18:1）。现命名是**一个原语 = 一个用途**（`gatePass`/`typePhase`/`statusDone`/`ledgerText`…），值由 WCAG 对比度**反解**得到：

- 校准方法（可复现）：对每个色相在 HSL 空间二分亮度，取「恰好越过阈值的最小改动」值再留 ~0.1 余量；
- 阈值两档（WCAG 2.x）：文本 ≥4.5:1；图形/填充 ≥3.0:1（统一按 3.3 校准留余量）；
- 表面只有两个：浅色 `#f8fafc`（`--anic-surface`）与暗色 `#0f172a`。

**L/D 后缀**（`palette.ts:24-27`）：`*L` = 浅色表面上的取值，`*D` = 暗色表面上的取值，**不可互换**（实测 `#2b823b` 浅色面 4.60 / 暗色面仅 3.2）。文本级令牌在 `SEMANTIC` 取 L 值、`SEMANTIC_DARK` 取 D 值，两者都由 `tests/contract/contrastContract.test.ts` 逐项测量。

**纪律**：组件**禁止**直接引用 palette（`clientRenderContract.test.ts` 拒绝任何绕过 `token()` 的颜色字面量）；`palette.ts` 只被 `tokens.ts` 消费。

### 1.2 语义层：`SEMANTIC` 42 键 + `SEMANTIC_DARK` 22 键

`SEMANTIC`（`tokens.ts:70-139`）42 个键，按域分组：门禁填充 5（`anic-gate-pass/fail/doubt/pending/skip`）、性能带 3（`anic-band-normal/warn/alarm`）、类型 9、状态 5、文本级 7、`surface/surface-hover/surface-active`、`focus-ring`、`border` 3、`text` 4、`on-accent`、`detail-surface`。

`SEMANTIC_DARK`（`tokens.ts:152-175`）是 `Partial<Record<TokenName, string>>` 的 **22 键覆盖表**：surface×3、border×3、text×4、pass/fail/doubt、ok/bad/warn、ledger 文本×7、band×3、detail。**门禁填充/类型色/状态色/on-accent 刻意不覆盖**——它们的 L 值在两个表面上同时 ≥3.3 校准，覆盖反而引入漂移风险（`contrastContract.test.ts:229`「非文本令牌不得被暗色覆盖」守卫钉死此决定）。

`export type TokenName = keyof typeof SEMANTIC;`——令牌名是**编译期封闭集合**，拼错名字过不了 typecheck。

## 2. `token(name)`：引用表达式（`tokens.ts:191`）

```ts
export function token(name: TokenName): string {
  return `var(--${name}, ${SEMANTIC[name]})`;
}
```

产出形状：`var(--anic-gate-pass, #...)` —— **变量引用 + 同源 fallback**。

**为什么内联 style 必须用它而不是裸 `var(--anic-pass)`**：宿主未注入变量时，裸引用会让属性计算为无效值，颜色回退到 `initial`——组件「看起来没坏但没样式」，这类缺陷在 DOM 断言里与「渲染正确」无法区分。**关于 fallback 的边界条件**：`var(--x, fallback)` 只在变量未定义或计算期无效时生效，不是 polyfill——注入必须真的发生。

## 3. `tokenCssBlock()`：作用域注入块（`tokens.ts:201`）

结构（`tokens.ts:201-209`）：

```css
[data-anic-workflow] {
  --anic-surface: #f8fafc;
  ... 亮色块由 Object.entries(SEMANTIC) 生成
}
[data-anic-workflow][data-anic-theme='dark'] {
  --anic-surface: #0f172a;
  ... 暗色块恰好发射 SEMANTIC_DARK 覆盖表
}
```

三个设计决定：

1. **亮色块由 `Object.entries(SEMANTIC)` 生成**——新增语义键自动进入 CSS 块，不存在「加了令牌忘了加变量」的漏配。
2. **暗色块恰好发射覆盖表**（`contrastContract.test.ts:289` 守卫），覆盖与不覆盖都是**显式决定**且被测试钉死。
3. **`TOKEN_SCOPE='[data-anic-workflow]'` 面板作用域**——**绝不写 `:root`**：本插件与宿主及其他插件共享同一个 document，写 `:root` 是全局污染；面板根节点带 `data-anic-workflow` 属性，变量只在该子树内生效。暗色切换不用 `prefers-color-scheme` 媒体查询，而是 `data-anic-theme='dark'` 属性选择器——由 `shellTheme.ts` 观察宿主真实主题驱动（宿主暗色 ≠ 系统暗色，跟宿主才是正确语义）。

## 4. 注入点：`useTokenCss()`（`src/client/components/panelTheme.ts`）

```ts
export function useTokenCss(): void {
  useEffect(() => {
    const id = 'anic-panel-css';
    if (document.getElementById(id)) return;          // 同页面多实例不重复注入
    const el = document.createElement('style');
    el.id = id;
    el.textContent = `${tokenCssBlock()}\n${PANEL_CSS}`;
    document.head.appendChild(el);
    return () => { el.remove(); };
  }, []);
}
```

cycle-18 起与 `useShellTheme()`（宿主主题运行时跟踪）同住 `components/panelTheme.ts`（T3 拆分自 WorkflowGraphPanel）；注入内容为「令牌块 + `PANEL_CSS` 面板交互态/响应式块」，style id 实为 `anic-panel-css`。

调用点在 `WorkflowGraphPanel.ts` 组件体内（`usePanelFetch` 之后），与 `useShellTheme()` 相邻。

## 5. 守卫面：三份契约测试

### 5.1 `tests/contract/clientRenderContract.test.ts`（源码形状守卫）

| 断言 | 保护什么 |
| --- | --- |
| 扫描集非空（`SRC_FILES >= 20`、`CLIENT_FILES >= 5`） | 静默空扫描 = 永久绿 |
| 反向自检：颜色字面量 regex 匹配 3 位/6 位十六进制与 `rgb()/rgba()/hsl()` 样例、**不误伤** `token()` 样例与 `url(#anic-spike-arrow)` | regex 写坏则守卫恒绿（`#fff` 三位形态是真实漏网案例，`WorkflowGraphPanel.ts` 曾躲过只认 6 位的扫描） |
| **`src/client` 下任何文件不得出现颜色字面量**（十六进制/rgb/hsl，豁免注释里的样例） | 颜色唯一归宿是 `palette.ts`——组件必须走 `token()` |
| 除 `tokens.ts` 外不得出现裸 `var(--anic-*)` | 变量引用必须带同源 fallback |
| 每个语义令牌产出 `var(--name, #hex)` 且与 `SEMANTIC` 同源 | fallback 不能是第二张表 |
| fallback **不得是另一个 `var()`** | 否则只是把失败推后一层 |

历史教训（行为断言 vs 源码 regex）：`token()` 用模板串拼 fallback，源码里不存在字面 `var(--anic-pass, #...)`，「扫描字面量」永远匹配 0 条——所以该断言写成**行为断言**（调 `token(name)` 检查返回值）。

### 5.2 `tests/contract/contrastContract.test.ts`（WCAG 逐项测量，11 用例）

| 用例 | 保护什么 |
| --- | --- |
| 覆盖完整性：每个令牌恰好被分类一次 | 未分类令牌即红（新令牌必须显式归类文本级/非文本级） |
| 两个表面取自真表且确实一深一浅 | 测量基座不可伪造 |
| 文本级令牌：浅色面全部 ≥4.5 且留余量 | 文本可读性（L 值） |
| 文本级令牌：暗色面全部 ≥4.5（**缺暗色覆盖即红**） | D 值；这条逼着文本级令牌必须进 SEMANTIC_DARK |
| 非文本级令牌：两表面都 ≥3.0 且留余量 | 图形/填充可读性 |
| 非文本令牌不得被暗色覆盖 | 两套门禁色各自校准的余量不被覆盖表破坏 |
| 字形墨色：五个门禁填充上全部 ≥4.5 | 旧的白墨必须被判红 |
| 反向自检：对比度公式本身正确（黑白 21:1/同色 1:1） | 测量工具自身可信 |
| 暗色覆盖表结构：键必须是已登记令牌、值必须是具体颜色而非 `var()` | 覆盖表形状 |
| tokenCssBlock：浅色块发射全部令牌、暗色块恰好发射覆盖表 | 注入不漏配、不越界 |

### 5.3 现状核对（cycle-28 校准）

- `src/client/` 下十六进制字面量：**0 处**（颜色唯一归宿 `palette.ts` 64 原语）；
- `token()` 直接 import 消费者 5 文件：`dataRow.ts`（tone 查表「判定结果→令牌的最后一跳」）/ `panelTheme.ts` / `sectionShell.ts` / `statusDot.ts` / `WorkflowGraphPanel.ts`；经由这些模块的常量（如 `gateColors.ts` 的 `GATE_COLORS` 全走 `token('anic-gate-*')`）**间接**覆盖全部特性域渲染器；
- `gateColors.ts:26-29` GATE_COLORS 五键全 token 化；`renderGraph.ts` import `token` 直接用于箭头/字形/文本色。

## 6. 落地程度（cycle-28 诚实陈述）

**已收敛**：原语层按角色命名 + WCAG 反解值；语义层 42+22 键；作用域注入不碰 `:root`；暗色跟宿主属性而非媒体查询；`src/client` 零颜色字面量；`contrastContract` 11 用例逐项测量。旧文档所述「4 套硬编码调色板仍在用、40+ 十六进制、hex 禁令守卫不存在」是**历史状态**，cycle-16~18 三轮已全部收口。

**尚未做**：无。已知边界：`PANEL_CSS`（`shared/panelCss.ts`）里的结构性样式（间距/圆角/交互态）不含颜色，不受颜色禁令约束。

## 7. 相关约定

**`.anic-*` CSS 类名**：脉冲动画类（`.anic-fail-node`/`.anic-live-dot`）现居 `src/client/components/statusDot.ts:18-37`（`FAIL_PULSE_STYLE` 含 `prefers-reduced-motion` 禁用 + `LIVE_PULSE_STYLE`，合并导出 `PULSE_STYLES`），cycle-16 B4 从 `gateColors.ts` 迁出；`StatusDot` 组件（`{color,size=10,pulse,border,anchor?}`）是全工程状态圆点的唯一实现。

**本工程没有 `.css` 文件**：全部样式是 React `createElement` 的内联 `style` 对象 + 运行时注入的 `<style>` 元素（`panelTheme.ts` 的令牌+面板块、`renderGraph.ts` 的脉冲块）。父工程的 `cg-` CSS 前缀约定**不适用于本工程**——详见 [开发规范-守卫与约束.md](开发规范-守卫与约束.md) §6。
